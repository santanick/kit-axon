## 환급 에디션(v31)
- 맑은소프트 벤치마크를 참고했으나, 맑은소프트보다 엄격하게 훈련생 · 교강사 · 관리자를 별도 서비스로 분리합니다. 인정 여부는 심사기관 확인이 필요합니다.
- `MODULE=learner|tutor|admin`: 서비스별 화면 · API · 역할 · 세션을 나눕니다. 비우면 기존 통합 동작입니다.
- `ADMIN_IPS`: 관리자 서비스 접속 허용 IP(쉼표, IPv4 CIDR 가능). `LEARNER_TID`: 훈련생 첫 화면의 기관.
- 교강사: 운영자가 발급한 계정, 담당 과정과 수강생만 조회, 저장 시 담당 과정의 운영 값만 반영, 계정 · 개인정보 열람 API 차단.
- 심사자: 지정한 훈련생 아이디의 본인인증 면제, 면제 기록(`cpl_log.kind = review`), 공단 데이터셋 제외. 다른 학습 제한은 그대로 적용합니다.
- 회원 정보: 생년월일 · 성별 입력 항목, HRD-Net CSV 대조(파일 미저장).
- 공단 전송 현황: 건수와 내려받기 기록만 표시합니다. 실제 전송 · 자동 전송 · 수동 재전송은 API 키 확보 후 구현합니다.
- 배포: `service/deploy-moel.sh`(3개 서비스), 사양 예시 `didisam/deploy/moel-edition.example.yaml`. 운영 비밀값 `SESSION_PEPPER`, `PII_KEY`는 `service/setup-gcp.sh`가 만듭니다. 실제 GCP 프로젝트에서 실행 검증은 아직 하지 않았습니다.
- 임시 비밀번호: 발급 계정은 비밀번호를 바꾸기 전까지 `/api/me`, `/api/password` 외 API를 쓸 수 없습니다.

## 기관 문서 개인정보 암호화(v31.1)
- 대상: `members`의 name · nick · email · phone · extra, `parents`의 name · phone, `codes`의 code, `admins`의 name · email(v31.6), `consults`의 title · summary · text · note · memo · transcript(v31.6), `msgs`의 to · title · body(v31.6), `crmLeads` · `crmHist` · `members[].crm` · `classes[].crmDay`(학원 CRM, v31.8), `inbox` · `chat`(v32.1).
- 방식: 저장 직전 AES-256-GCM(`PII_KEY`), 읽은 직후 복호화. 값 앞에 `enc1:`이 붙습니다. `PII_KEY`가 없으면 평문으로 저장하며, 운영 서버는 키가 없으면 시작하지 않습니다.
- 기존 평문: Node 서버 시작 시 전환합니다. Java만 운영하면 다음 저장 때 전환됩니다.
- `PII_KEY`를 잃으면 대상 항목을 복구할 수 없습니다. 키는 비밀 관리 서비스와 별도 안전한 장소에 백업합니다.
- 대상 밖: 게시글 본문, 학습 활동 로그 IP. 심사 전에 범위를 확인합니다.
- 홈페이지 이미지(v34.5 `/api/media`): `media` 표(기관별 RLS, 기관 삭제 시 함께 삭제)에 저장하고 공개 주소로 내보냅니다(암호화 대상 아님). 위치 등 메타데이터(JPEG EXIF · XMP · IPTC · 주석, PNG 텍스트 · 시각 청크, WEBP EXIF · XMP)는 브라우저와 서버에서 모두 지우고, 사진 속 얼굴 · 개인정보는 운영자가 올리기 전에 확인합니다(AI로 보낼 때는 한 줄 안내 후 운영자가 보낼 때만).
- 키 교체: 자동 교체 기능은 없습니다(미구현). `PII_KEY`는 문서 암호화뿐 아니라 이메일 · 휴대폰 검색 인덱스와 SNS 식별값 해시에도 쓰이고, 해시 원문은 복구할 수 없어 키만 바꾸면 기존 계정 로그인 조회가 끊깁니다. 교체가 필요하면 점검 시간에 다음 순서로 진행합니다. ① DB와 키 백업 ② 옛 키로 문서 · 개인정보를 복호화하고 새 키로 재암호화하는 일회성 작업 실행 ③ 이메일 · 휴대폰 인덱스를 원문에서 재생성 ④ SNS 계정은 다시 연결(해시 원문 없음) ⑤ 서버 키 교체 후 로그인 · 조회 확인. ②~④의 작업 스크립트는 교체가 결정되면 별도로 만듭니다. 문서 암호화 키와 인덱스 키를 분리하면 부담이 줄어들므로, 운영 데이터가 쌓이기 전에 결정합니다.

## 서버 강제(v31.6)
- 진행 조건: `seq`가 켜져 있으면 이전 동영상 · 진행평가를 마치지 않은 학습 기록을 `seq_locked`(403)로 거절하고, 진행평가가 남으면 시험 시작을 `exam_quiz`, 진도율이 `rate` 미만이면 `exam_rate`로 거절합니다. 차시 완료는 학습 로그의 초 합계가 차시 시간 × `itemMin`% 이상일 때입니다.
- 진행평가 완료 값은 학습자 진도 저장값(`learner_progress`)을 씁니다. 진행평가 채점이 서버로 옮겨지기 전까지는 이 항목만 브라우저 입력에 의존합니다.
- 본인인증 이력: 서버 설정 `IDV_ENFORCE=1`일 때 입과 인증(`00`) 없는 학습 · 출결 · 시험, 당일 인증(`01`, 입과 당일은 `00`도 인정) 없는 학습을 `idv_required`(403)로 거절합니다. mOTP를 켠 과정은 60분 안의 평가 인증(`02`) 없는 시험 시작도 거절합니다. 학습자 화면은 이 응답을 받으면 인증 창을 다시 엽니다. 인증 제공사가 없으면 모든 학습이 막히므로 기본은 꺼짐이며, 연동 후 켭니다.
- 수료 판정: `GET /api/cpl/completion`이 학습 로그와 서버 채점으로 과정 · 훈련생별 진도율, 평가별 최고 점수, 수료 여부를 돌려줍니다. 평가가 여러 개면 가장 낮은 점수로 판정합니다. 실서버의 모니터링 · 수료 보고 · 공단 제출 파일은 이 값을 씁니다.
- 무활동 세션: `learner_sessions.last_at`을 기준으로 `idleH` 시간이 지나면 서버가 세션을 지웁니다(401).

## RES_NO 처리 방침
- 체크리스트 예시: 사업주 13자리, 내일배움 7자리(생년월일 + 성별 1자리). 실제 전송 형식은 공단 API 매뉴얼을 따릅니다.
- 개인정보 보호법 제24조의2는 주민등록번호 처리에 법률 · 대통령령 등의 구체적 근거를 요구합니다. 동의만으로는 처리하지 않습니다.
- 국민 평생 직업능력 개발법 시행령 제52조의2의 처리 주체는 고용노동부장관과 위임 · 위탁받은 자 등입니다. 일반 훈련기관의 처리 근거는 확인하지 못했습니다.
- 현재 수집 · 저장 · 전송하지 않습니다. 데이터셋의 RES_NO는 항상 비어 있으며, 회원 추가 정보에 주민등록번호로 보이는 값이 있으면 데이터 연계 탭에 경고합니다.
- 공단 API 연동 전에 API 매뉴얼과 공단 회신으로 형식과 근거를 확인하고 법무 검토를 받습니다. 그 전에는 저장 기능을 만들지 않습니다.
- 연동 시 조건: `pii` 스키마에 AES-256-GCM 저장, 화면 마스킹, 조회 로그, 회원가입 필수 입력 금지, 보유기간 경과 후 파기.

## 쉬운 게시 경고 · 법정 교육시간(v35)
- 문제은행 배수(별표 1, 기본 3배수): 게시 버튼 경고를 '시험 문제를 출제 문항 수의 3배 이상 준비'라는 쉬운 말로 바꾸고 [AI로 문항 채우기]를 둡니다. 출제 수가 없으면 지금 문항 수(최대 10)를 출제 수로 정하고 모자란 문항을 AI 초안(`ai: 1`)으로 보탠 뒤 게시합니다(`cplBankFill`).
- 과정 만들기가 자동으로 넣은 시험(`autoGen: 1`, 출제 수 미설정)은 사용자가 만든 것이 아니므로 게시 경고에서 뺍니다. 점검표(e-bank)와 차시 · 평가 탭에는 그대로 보입니다. 출제 수를 정하면 경고 대상이 됩니다.
- 법정 교육시간(`cplLegalHours(과정 또는 초안)`): 템플릿 id 또는 과정 이름으로 찾고, 총 시간(`hours`, 없으면 차시 수 × 1차시 분)이 모자라면 점검표 위와 차시 · 평가 탭에 경고합니다.

| 대상 | 기준 | 근거 |
|---|---|---|
| 요양보호사 실기(v-care) | 114시간 | 노인복지법 시행규칙 별표 10의3(2024. 1. 1. 시행, 이론 126 · 실기 114 · 실습 80, 총 320) |
| 요양보호사 신규 과정 | 320시간 | 같은 별표 |
| 직장 내 성희롱 예방(c-harass) | 연 1회 1시간 | 남녀고용평등법 시행령 제3조 |
| 4대 폭력 예방(p-4v) | 연 1회 각 1시간(합 4시간) | 양성평등기본법 제31조 · 성매매방지법 제5조 · 성폭력방지법 제5조 · 가정폭력방지법 제4조의3 |
| 관리감독자 정기교육(v-safe) | 연 16시간 | 산업안전보건법 시행규칙 별표 4 |
| 공직자 청렴교육(p-anti) | 연 2시간 | 부패방지권익위법 제81조의2 |

과정 만들기 흐름(v35.3)에서는 2단계(훈련시간 · 차시 목록) 맨 위에 미달 경고와 [법정 시간에 맞추기]를 둡니다. 차시는 60개까지이므로 1차시 시간을 늘려 맞추고(직업훈련 집체 · 혼합은 1차시 50분~8시간, 원격은 25분~1시간), 직업훈련은 '총 훈련시간(시간)'을 적으면 차시 수 · 차시 인정 시간을 거꾸로 계산합니다. 요양보호사 실기 템플릿(v-care)은 38차시 × 3시간 = 114시간으로 시작합니다. 미달인 채 [개설하기]를 누르면 '인정받지 못할 수 있다'는 확인 창을 한 번 더 띄우고(막지는 않음), 학습자 사이트 게시 때도 공개 과정 중 미달이 있으면 같은 확인 창을 띄웁니다.

수치는 공개 법령 기준의 자체 안내이며 기관이 원문으로 다시 확인해야 합니다. 바꾸면 `didisam/compliance.js`의 `LEGALH`와 `tests/ui/compliance.js`를 함께 고칩니다.

## 소명 · 혼합훈련 · 문서 초안(v31.6)
- 모니터링 소명: `S.cpl.claims`에 접수일, 제출 기한, 훈련생, 지적 내용, 소명 내용, 상태를 저장합니다. 기한이 지나면 표시합니다. 공단 제출과 자동 수신은 연동 전까지 하지 않습니다.
- 혼합훈련 데이터셋: `CONTENTS_HIST`에 평가 콘텐츠를 포함하고, `ATTEND_RSLT_CT_HIST`는 콘텐츠별로 동영상은 학습 시간 ÷ 차시 시간, 평가는 그 평가의 점수를 씁니다. 필드 해석은 공단 API 매뉴얼 확보 후 다시 확인합니다.
- 최초 비밀번호: 이메일 인증번호로 가입한 계정은 현재 비밀번호 없이 처음 한 번 설정할 수 있고, 이후에는 현재 비밀번호가 필요합니다.
- 문서 초안: 증빙 탭에서 LMS 운영 · 관리 규정, 정보보안 규정, 백업 · 복원 일지, 장애 대응 절차, 자체평가보고서 초안을 표준 문서함에 만듭니다. 공단 공식 서식이 아니며, 항목은 증빙자료 목록과 시스템 설정값을 바탕으로 합니다. 기관 사실과 심사기관 안내로 확인합니다.

## 서버 채점(v30.1)
- 규정이 켜진 고용노동부 프로필의 시험(`type: exam`)은 게시본에 문항과 정답을 싣지 않습니다.
- 응시 시작 때 서버가 출제 수만큼 무작위로 뽑아 문항만 내려 주고, 제출 시 서버가 채점합니다. 정답은 학습자에게 보내지 않습니다.
- 재시작해도 같은 응시와 종료 시각을 유지하고, 종료 후 60초가 지나면 답안을 인정하지 않습니다. 원본은 `cpl_exam`에 있습니다.
- 학습시간은 직전 기록 이후 실제 경과 시간(+5초)까지만 적립합니다.

## 출결 계산(v33)
- 학습자 화면(나의 출결) · 클래스 출결(출석률 80% 미만 경고) · 규정 준수 「출결 환산」은 같은 공용 함수 `didisam/attcalc.js`(`DDAtt`)를 씁니다. 별도 근거 수치가 없어 기존 운영자 「출결 환산」 식을 기준으로 삼았습니다.
- 대상 회차: 출결이 입력된 회차 + 어제까지 지난 미입력 회차(결석으로 셈). 오늘 회차는 입력 전이면 세지 않고, 수강 제외 회차는 뺍니다. 회차별 출결과 QR 출결(`mid:n`)을 모두 셉니다.
- 고용노동부 프로필(규정 준수 켜짐)은 지각 · 조퇴 · 외출 3회를 결석 1회로 환산합니다. 그 밖의 기관은 지각 · 조퇴 · 외출을 출석으로 인정합니다.
- 출석률 = (대상 회차 − 환산 결석) ÷ 대상 회차. 80% 미만이면 운영자 화면에서 경고하고, 학습자 화면에 80% 기준을 안내합니다.
- 진도 · 수료(v33): 학습자 「내 훈련」의 진도는 학습 기록으로 인정한 차시 비율과 운영자 기록(`prog.p`) 중 큰 값이고, 수료는 진도율 `rate` 이상 + 모든 평가 `pass` 이상으로 운영자 `cplDone`과 같은 식입니다(발급된 수료증만으로 수료 표시하지 않음).

## 알려진 위험
- 차시 학습시간은 경과 시간 내에서 제한하지만, 영상이 실제로 재생됐는지까지 서버가 증명하지는 않습니다.
- 퀴즈(`type: quiz`)와 영상 구간 퀴즈는 연습용으로 보고 브라우저 채점을 유지합니다. 심사기관이 평가로 본다면 서버 채점 대상에 포함해야 합니다.
- 수료 표시는 학습자 화면 계산이며, 운영자 화면의 수료 보고가 서버 채점 점수를 기준으로 합니다. 진도 원본(`prog.p`)의 서버 판정은 후속 과제입니다.
- (v32.8) 데모 판정 `cplDone`: 평가 항목이 있는 과정은 평가 점수가 없으면 수료로 보지 않습니다(학습자 화면과 같은 기준). 평생교육원 프로필에는 고용노동부 제3자 제공 · 부정훈련 문구를 표시하지 않고, 앱 화면 첫 화면에는 유의사항 상자를 끼워 넣지 않습니다(과정 입과 시 확인 창에 [나중에 볼게요] 추가). 튜터의 수료 기준 답은 게시된 규정(진도율)을 우선합니다.

## 수료 판정 한 곳(v38)
- 운영자 수료 판정은 `didisam/mods.js`의 `clsDone` 한 곳입니다. 수료 판정 · 수료증 발급 · HRD-Net 보고(수료 요건 충족 · 보고 파일) · 수료보고 CSV · 공단 데이터셋(`PASS_FLAG`) · 이수 현황 엑셀이 모두 이 값을 씁니다.
- 고용노동부 프로필(규정 준수 켜짐)은 `cplDone`(진도율 `rate` 이상 + 모든 평가 `pass` 이상)에 더해, 출결 수업(오프라인 · 라이브 · 회차)이 있으면 **출석률 80%(`DDAtt.MIN`) 이상**이어야 수료입니다. 국민내일배움카드 운영규정의 소정훈련일수 80% 이상 출석 기준을 따르며, 출결 수업이 없는 원격 과정은 출석률을 보지 않습니다.
- 출석률은 `clsAtt`(= `DDAtt.of`) 한 곳입니다. 출결 탭 · '출석률 80% 미만' 경고 · HRD-Net · 규정 준수 '한눈에'는 같은 숫자를 사람 수(중복 제외)로 셉니다.
- 학습자 화면의 수료 표시(강좌 요약 · 수료증 보기 · 내 학습)는 `myStats().done` 한 곳이며, `lcompliance.js`가 같은 식(진도율 · 평가 점수 · 출석률)으로 계산합니다. 진도 100%만으로 '수료'를 띄우지 않습니다.
- 규정 준수 과정의 최종평가는 시험 규칙에 통과 점수가 없어도 `pass`를 통과 점수로 안내하고, 수료 기준 문구에 평가 · 출석 기준을 함께 적습니다.
- 평가(시험)가 없는 운영 중 직업훈련 과정은 점검표(`e-eval`) · 한눈에 · 게시 전 확인 창에서 알립니다(평가 점수가 수료 기준이므로).
- HRD-Net 화면의 부정훈련 의심은 실제 학습 기록(여러 IP 접속 · 하루 학습시간 한도 초과)에서만 만들고, 없으면 '없음'으로 표시합니다.
- 실서버의 `GET /api/cpl/completion`(진도 · 평가)은 출결을 보지 않습니다. 화면 판정은 서버 판정 위에 출석률 기준을 더해 계산합니다. 서버 판정에 출결을 넣는 것은 후속 과제입니다.
