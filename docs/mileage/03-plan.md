### 0.1 대표님 결정 (2026-11-14) — 이 문서 전체의 상위 규칙
| # | 결정(원문 요지) | 설계 반영 | 위치 |
|---|---|---|---|
| D1 | 국비 직업훈련 과정(내일배움카드 · 고용노동부 지원)은 금전성 보상을 「막아」 | **시스템 강제 차단**(기관 설정으로 풀 수 없음). 대상: 장학 · 학원비 · 수강료 차감 · 쿠폰 · 현금성 사은품. 과정 단위 「국비 지원 과정」 표시, 해당 과정 적립은 배지 · 인정 기록만. 같은 기관의 비국비 과정은 기관 정책을 따름 | 3.7, 5장 ⑧, 04 §2 · §4 |
| D2 | 「학원에서 결정하게 해줘 … 정책안만 수립하고 각 교육기관에서 수정 및 보완 혹은 마일리지 제도를 사용하지 않게도」 | 디디쌤은 기관 유형별 **권장 정책안(템플릿)만** 제공. 기관은 **모든 값**(배점 · 한도 · 차감 상한 · 유효기간 · 보상 종류 등)을 수정 · 보완 가능. 디디쌤 값은 「권장값」 표시로만. 제도 전체 끄기 가능, **기본값 = 끔**, 켜기는 마법사로 | 2.4, 2.3, 5장 |
| D3 | 미성년 대상 기관의 공개 순위 · 감점은 기본 끔, 기관이 켤 수 있게 | 기본 끔 + 기관 선택권. 켤 때 **영향 안내(수치심 · 역효과 연구) → 운영자 확인 → 변경 이력** | 7.3 |

D2에 따라 이 문서의 숫자 · 잠금 기본값은 모두 「권장값」입니다. 기관이 바꿀 수 없는 것은 **D1 국비 차단, 원장 불변(삭제 금지), 운영자 본인 계정 지급 금지** 세 가지뿐입니다(2.4).

디디쌤 시사점: 「포인트 지급 기능」이 아니라 **「기관 보상 정책을 안전하게 돌리는 원장 + 학습자 자기 동기 화면」**으로 설계해야 대학 · 학원 · 기업에 같은 코드로 팔 수 있습니다.

## 2. 정책 엔진 (기관별 설정)

### 2.1 정책 엔진 8요소 (R1 §10 공통 패턴 반영)
엔진은 기관 유형과 관계없이 **하나**이고, 정책 1벌 = 아래 8요소입니다. 템플릿(5장)은 이 8요소의 기본값 묶음일 뿐입니다.

| # | 요소 | 붙는 곳 | 칸 · 값 예 | 근거(R1) |
|---|---|---|---|---|
| 1 | **적립 조건** | 규칙 | 트리거(2.2 표) + 조건 `{cls:'*', minScore:80, firstTry:true}` + 대상(전체 · 과정 · 기수 · 소속) + 기간(캠페인 시작 · 끝) + 신뢰 최소(A만 / B 이상 / C 허용) + 성격(`achievement` 성취형 · `participation` 참여형) | 패턴 1 「완료 · 성취 단위」 |
| 2 | **배점** | 규칙 | 고정 300P / 구간(80↑ 50 · 90↑ 100) / 단위당(10분당 1P) / 원천 값(비교과 `mileage`) | 명지대 항목별 배점 |
| 3 | **한도** | 규칙 · 항목군 · 기관 | 규칙별 하루 · 주 · 월 · 학기 · 학년 · 전체 상한, 1회성(없음 · 평생 1회 · 대상마다 1회 · 하루 1회), **항목군 한도**(예: 「자격증 · 어학」 학기 100점), 1인 하루 총 상한, **지급 주체 한도**(강사별 월 지급 한도), **기관 · 지점 예산**(월 · 학기 P 또는 원) | 패턴 2, 칭찬모아 강사별 한도 · 충전 범위 |
| 4 | **기준점(문턱)** | 보상 · 등급 | 보상 전환 최소 누적점(예: 장학 신청 15점 · 200점), 최소 사용 P, 등급 진입점 | 패턴 3 |
| 5 | **승인** | 규칙 · 보상 | 자동 / 운영자 확인 / n점 넘으면 확인 / **증빙 제출 → 담당자 확인**(AI 1차 판독, 부결 사유 공개) / 2단계(담당 → 기관) | 패턴 5 원광대 · 삼육대 |
| 6 | **만료** | 규칙(적립 건) · 정책 | 적립 건별 만료일(적립일 + n개월 / 학기 · 학년 말 / 없음), 선입선출 차감, **소멸 6개월 전부터 매월 고지**, 등급별 만료 완화(선택), 졸업 · 퇴원 · 수료 시 처리 | 패턴 6 신한카드 · Starbucks |
| 7 | **보상 전환** | 보상 | 3장 카탈로그. 장학은 3방식(점당 정액 · 등급 정액 · 1P=1원), 학원비 차감 · 쿠폰 · 굿즈 · 리워드 숍. 전환 가능 잔액 = 성취형 · 신뢰 A/B 적립분 | 패턴 4 |
| 8 | **인정 기록** | 규칙 · 등급 · 보상 | 포인트를 다 써도 남는 영구 기록: 배지 · 인증서(`certkit.js`) · 역량우수 기록, v42.2 Open Badges 3.0 내보내기 | 패턴 10, U of T CCR |

규칙(1~3 · 5 · 6 · 8을 가진 적립 단위)과 보상(4 · 5 · 7)은 따로 저장하고, 정책(기관 1벌)이 둘을 묶습니다. 운영자 수동 지급은 **경쟁 지표(순위 · 리그)에서 제외**합니다(R1 §11-7).

규칙은 **버전**을 가집니다. 적립 줄은 「규칙 ID + 버전」을 남겨, 규칙을 바꾼 뒤에도 과거 적립의 근거를 설명할 수 있습니다. 규칙 변경은 **앞으로의 사건에만** 적용하고, 소급 적립은 「미리보기 → 확인」을 거친 별도 작업으로만 합니다.

| `course_done` | 과정 이수 | 대상 과정 | 고정 | 과정마다 1회 | B(수료증 발급 `a2AutoCert`) · A(cpl 수료 · 학사) | 환불 · 수료 취소 시 자동 취소(4.4) |

성격 구분: `signup` · `first_login` · `attend_day`(접속형) · `tube_goal`은 **참여형**으로 고정합니다. 참여형은 배지 · 등급 · 스트릭에만 쓰이고 현금성 전환 잔액에 들어가지 않습니다(R1 §11-1: 참여만 하면 주는 예상된 물질 보상은 내재 동기를 낮춤). 나머지는 성취형입니다. 감점(마이너스 배점) 규칙은 기본 꺼져 있고 7.3 절차로 켠 기관만 만들 수 있습니다. 그 밖의 마이너스 줄은 취소 · 정정 · 소멸 · 사용에만 생깁니다.

### 2.3 규칙 템플릿 · AI 초안 흐름
「사람은 확인만, AI가 처리」 원칙에 맞춰 운영자가 빈 화면에서 규칙을 처음부터 만들지 않게 합니다.

| 단계 | 화면 | AI · 시스템이 하는 일 | 운영자가 하는 일 |
|---|---|---|---|
| ① 시작 | 스튜디오 › 마일리지(처음) | 기관 유형 · 세부(`S.org.type` · `S.org.ed`) · 결제/원장 사용 여부 · 규정 프로필 · 과정 수 · 최근 30일 학습 사건 수를 읽습니다 | 질문 1개만 답합니다: 「한 달 보상 예산(또는 학기 장학 예산)이 있습니까?」(없음 = 비현금형) |
| ② 초안 | 「추천 정책 초안」 카드 | 5장 템플릿을 고르고, 과정 · 시험 이름을 채운 규칙표 + 보상 카탈로그 + **모의 계산**(지난 30일 사건에 적용했을 때 적립 P · 환산 금액 · 1인 평균 · 상위 10% 1인 값)을 만듭니다. AI 사용 불가 시 템플릿 그대로 | 표를 봅니다. 고칠 칸만 누릅니다 |
| ③ 점검 | 같은 카드 하단 「확인할 점」 | 규정 · 예산 경고를 자동으로 붙입니다(예: 국비 과정 금전성 차단 안내, 예산 초과 예상, C 신뢰 규칙이 현금성 보상과 연결됨) | 경고를 읽습니다 |
| ④ 켜기 | [확인하고 켜기] | 규칙 버전 1로 저장 · 감사 기록 · 학습자 화면 안내문 자동 생성(적립 기준 · 소멸 · 보상) | 확인 1번 |
| ⑤ 운영 | 「한눈에」 | 주 1회 「정책 점검」 제안(예: 「과제 제출 규칙이 지급의 70%를 차지합니다. 상한을 낮출까요?」) | 확인 또는 무시 |

AI 출력은 규칙 스키마(04 §2)로 검증합니다. 스키마에 맞지 않거나 시스템 차단(국비 과정 금전성)을 어기면 버리고 템플릿으로 돌아갑니다. AI는 규칙을 **켜지 않습니다**. 초안의 모든 숫자에는 「권장값」 표시가 붙고, 운영자가 바꾼 값은 「기관 설정」으로 표시됩니다.

### 2.4 정책 소유 · 제도 켜고 끄기 (D2)
| 항목 | 설계 |
|---|---|
| 소유 | 정책은 기관의 것입니다. 디디쌤은 권장 정책안(템플릿 · AI 초안)만 제공하고, 기관이 수정 · 보완 · 삭제 · 추가합니다 |
| 수정 범위 | 8요소의 **모든 값**: 트리거 켜기 · 조건 · 배점 · 한도 · 기준점 · 승인 · 유효기간 · 보상 종류 · 교환 비율 · 학원비 차감 상한 · 순위 · 감점 · 알림 · 신뢰 잠금 · 참여형 전환 잠금 · 예산 |
| 권장값 표시 | 편집 칸마다 「디디쌤 권장값: 30%」를 회색 보조문으로 보이고, 권장 범위를 벗어나면 이유 한 줄(예: 「청구서의 50%를 넘는 차감은 매출 변동이 커질 수 있습니다」)만 보입니다. 막지 않습니다 |
| 제도 기본값 | **끔**. 스튜디오 「마일리지」 탭은 보이되 첫 화면은 「마일리지 제도 시작하기」 마법사 카드 1장 |
| 켜기 마법사 | ① 쓸지 여부 · 목적(동기부여 / 장학 · 할인 연계) → ② 권장 정책안 확인 · 수정(AI 초안 + 모의 계산) → ③ 보상 종류 선택(쓰지 않음 가능) → ④ 학습자 안내문 미리보기 → [확인하고 켜기] |
| 끄기 | 「제도 사용 안 함」은 언제든 가능. 적립 · 보상이 한 번이라도 있었다면 3.6 제도 종료 절차(고지 · 교환 기간 · 잔액 정리)로 진행, 없었다면 즉시 끔 |
| 부분 사용 | 보상 없이 「적립 · 배지만」, 등급 없이 「잔액만」 등 요소별 끄기 가능 |
| 바꿀 수 없는 것 | ① 국비 직업훈련 과정 금전성 보상 차단(D1) ② 원장 불변(삭제 대신 반대 줄) ③ 운영자 본인 계정 지급 금지. 이 셋은 제품 규칙입니다 |
| 변경 이력 | 정책 변경은 모두 버전 · 변경자 · 시각 · 전후 값을 감사 기록에 남기고, 「설정 › 변경 이력」에서 봅니다 |

디디쌤 시사점: 경쟁 서비스는 포인트 규칙을 운영자가 직접 짜게 합니다. 디디쌤은 「기관 유형 + 실제 학습 데이터로 모의 계산한 초안」을 먼저 보여 주는 것이 차별점이고, 예산 사고(과지급)를 미리 막습니다.

### 3.2 교환 규칙(보상마다)

| 칸 | 뜻 | 기본 |
|---|---|---|
| 교환 비율 | 1P당 가치(원) 또는 보상 1개당 P | 기관 설정(학원비 차감 예: 1P = 1원) |
| 최소 사용 | 한 번에 쓸 최소 P | 1,000P(소액 반복 신청 방지) |
| 최대 사용 | 한 번 · 한 달 · 청구서 1건당 최대 | 학원비 차감 상한은 **학원이 정합니다**(D2). 디디쌤 권장값: 청구서 금액의 30% |
| 사용 단위 | 몇 P 단위로 쓰는지 | 100P |
| 재고 · 1인 한도 | 굿즈 재고, 1인 기간 한도 | 굿즈 1인 월 1개 |
| 대상 | 등급 · 과정 · 소속 | 전체 |
| 신뢰 제한 | C 사건 적립분으로 교환 가능한지 | 권장값: 현금성(장학 · 학원비 · 쿠폰)은 **A · B 적립분만**. 기관이 경고 확인 후 변경 가능(D2) |
| 국비 과정 적립분 | 국비 지원 과정에서 생긴 적립 | **금전성 보상에 쓸 수 없음(시스템 고정, D1)**. 배지 · 인정 기록만 |

신뢰 제한을 지키는 방법: 적립 줄마다 신뢰 등급을 남기고, 현금성 보상은 「A · B 적립 잔액」 안에서만 쓰게 합니다(04 §2.2 `convertible`). 학습자 화면에는 「전체 마일리지」 하나만 보이고, 현금성 보상 신청 시 쓸 수 있는 양을 따로 안내합니다.

### 3.3 승인 흐름
1. 학습자가 보상을 고르고 쓸 P를 정합니다(최소 · 최대 · 단위 자동 맞춤). 서버가 잔액 · 한도 · 재고를 다시 계산합니다.
2. 신청과 동시에 **P를 「사용 대기」로 잡아 둡니다**(이중 사용 방지). 잔액 표시는 「쓸 수 있는 P」에서 빠집니다.
3. 자동 승인 보상은 즉시 이행(쿠폰 코드 발급 · 배지 수여). 확인 보상은 「신청 · 승인」 탭에 쌓이고, AI가 「확인할 점」(부정 의심 · 한도 근접)을 붙여 줍니다.
4. 승인 → 이행 기록(청구 줄 ID · 쿠폰 코드 · 인증서 번호 · 수령일). 반려 → 잡아 둔 P 복원 + 사유 알림.

### 3.4 회수 · 취소(환불 · 부정 적발)

| 상황 | 처리 | 학습자 화면 문구(해요체) |
|---|---|---|
| 과정 환불(v41 `led_refund` 완료) | 그 과정에 묶인 적립(`course_done` · `lesson_done` · `exam_score`)을 취소 줄로 상쇄 | 「○○ 과정 환불로 적립된 320P가 취소됐어요.」 |
| 수료 취소 · 성적 정정 | 해당 적립 취소, 정정 후 다시 맞으면 재적립(멱등 키 분리) | 「성적 정정으로 마일리지가 다시 계산됐어요.」 |
| 이미 쓴 P가 취소되는 경우 | 잔액이 음수가 될 수 있습니다. **음수 동안 보상 신청을 막고**, 다음 적립으로 메웁니다. 현금 청구는 하지 않습니다(R2 확인) | 「취소된 마일리지 50P를 다음 적립에서 먼저 채워요.」 |
| 학원비 차감 후 환불 | 환불 금액 산정은 **실제 낸 금액 기준**(v41 규칙 유지), 차감에 쓴 P는 환불 비율만큼 복원 또는 소멸(기관 설정, R2 확인) | 「환불로 차감에 쓴 1,200P 중 600P를 돌려드렸어요.」 |
| 부정 적발(7장) | 의심 → 보류(적립 「대기」) → 운영자 확정 시 취소 · 보상 회수 · 배지 회수. 처분 사유를 감사 기록에 남김 | 「확인이 필요한 적립이 있어 잠시 보류됐어요. 문의는 요청함으로 보내 주세요.」 |
| 운영자 실수 지급 | 「조정」 줄로 상쇄(원 줄 삭제 금지) | 「운영자가 잘못 적립된 100P를 바로잡았어요.」 |

### 3.5 대학 장학금 환산 3방식 (R1 §3 국내 대학 사례)
| 방식 | 계산 | 예(R1 사례 값) | 예산 초과 시 | 공통 필수 설정 |
|---|---|---|---|---|
| ① 점당 정액 | 정산 대상 점수 × 1점당 금액, 1인 상한 | 1점 = 1,000원, 1인 최대 20만 원(가톨릭관동대 2024-1 공지) | 기관 선택: 선착순 신청 마감 / 비례 축소 / 점수 상위 순 | **최소 기준점**(예: 15점 · 200점), **항목군 한도**(학기 · 학년), **증빙 승인**(증빙 실적은 승인된 것만 정산 대상), 정산 기간(학기), 정산 후 점수 차감 여부, 1인 상한 |
| ② 등급별 정액(인원 한정) | 누적점 구간 → 등급 → 등급별 정액, 등급별 인원 상한 | A · B · C 50 · 30 · 20만 원, 인원 한정(R1 §3) | 등급별 인원 상한으로 자동 제한(동점은 기관 규칙: 최근 학기 점수 · 항목 다양성) | 위와 같음 + 등급 기준점 · 인원 |
| ③ 1P = 1원 | 정산 대상 P를 그대로 원으로 | 1P = 1원 | 1인 상한 · 총예산 비례 축소 | 위와 같음 |

- 정산 대상 P는 「이번 학기 적립 중 전환 가능한 것」(성취형 · 신뢰 A/B · 승인 완료)입니다. 이월 여부는 기관 설정입니다.
- 정산안은 학번 · 학과 · 점수 · 금액만 담고, 계좌 등 지급 정보는 받지 않습니다(학교 장학 시스템에서 지급).
- 「역량우수상」처럼 금액 없는 인정형 정산(상위 n명 인정 기록)도 같은 화면에서 만들 수 있습니다(요소 8).

### 3.6 제도 종료(포인트 폐지 · 축소) 절차 (R1 §6 · §11-5 · §11-6)
기관이 비용 부담 등으로 제도를 끝내거나 보상을 줄일 때, 갑작스러운 일괄 소진으로 신뢰를 잃지 않도록 절차를 제품에 넣습니다.

| 단계 | 내용 | 기본값(R2 확인) |
|---|---|---|
| ① 종료 예고 | 운영자가 종료일 · 사유 · 잔액 처리 방식을 정하면 학습자 전원 알림 + 「내 마일리지」 상단 안내 | 종료일은 예고일 + 6개월 이상(소멸 사전 고지 관행과 맞춤) |
| ② 신규 적립 중단 | 예고일 또는 지정일부터 적립 규칙 끔(인정 기록 · 배지는 계속 가능) | 운영자 선택 |
| ③ 교환 기간 | 종료일까지 보상 교환 허용, 필요 시 교환 문턱(최소 사용 P) 낮춤 | 문턱 0으로 낮추기 권장 |
| ④ 잔액 정리 | 기관 선택: 소멸 / 일괄 환산(쿠폰 · 차감 · 장학 정산) / 다른 제도로 이관 | 매월 잔액 고지(예고 후 매월 1회) |
| ⑤ 기록 보존 | 원장 · 인정 기록은 보존 기간 동안 조회 가능 | 감사 기록 남김 |

부분 축소(교환 비율 인하 · 보상 삭제)도 같은 절차를 따르며, **이미 적립된 줄의 만료일 · 가치는 소급해 줄이지 않는 것**을 기본으로 합니다(R2 확인).

### 3.7 국비 지원 과정 금전성 보상 차단 (D1, 시스템 강제)
| 항목 | 설계 |
|---|---|
| 표시 | 과정(강좌) 설정에 「국비 지원 과정」 표시(내일배움카드 · 고용노동부 지원 등). 직업훈련 기관(`voc`)과 규정 프로필 `moel-entrust` · `moel-self`가 켜진 기관에서 새 과정은 **기본 표시 켬**, 그 밖의 기관도 과정마다 켤 수 있음. 국비 표시 변경은 owner만, 변경 이력 기록 |
| 적립 | 국비 과정에서 생긴 사건의 적립 줄은 `funded=true`, `convertible=false`로 고정. 배지 · 인정 기록(`record`) · 등급 · 스트릭에는 반영 |
| 차단 대상 | 장학 환산 · 학원비 · 수강료 차감 · 쿠폰(수강권) · 현금성 사은품(굿즈 · 기프티콘 등 금전 가치 있는 것) |
| 차단 방식 | ① 국비 과정 적립분은 금전성 보상 소진 대상에서 제외(선입선출에서 건너뜀) ② 국비 과정 청구서 · 결제에 마일리지 차감 줄 · 쿠폰 적용 거절(`funded_blocked`) ③ 국비 과정을 대상으로 한 금전성 보상 규칙 · 카탈로그 저장 거절 ④ 서버가 매번 다시 확인(화면 설정 · AI 초안 · 수동 지급 모두 같은 검사) |
| 풀 수 없음 | 기관 설정 · 운영자 · AI 어느 경로로도 해제 불가. 바꾸려면 디디쌤 제품 배포(통합 담당)만 |
| 비국비 과정 | 같은 기관의 비국비 과정은 기관 정책을 그대로 따름(D1). 학습자 한 명이 두 종류 과정을 들으면 잔액은 하나로 보이되 「금전성 보상에 쓸 수 있는 P」에서 국비 과정 적립분이 빠짐 |
| 학습자 문구 | 「국비 지원 과정에서 쌓은 마일리지는 배지와 학습 기록으로 남아요. 할인 · 장학에는 쓸 수 없어요.」 |
| 근거 | 국비 과정 수강료 성격 보상의 부정수급 위험(R1 §7 · §11-8), 조문 근거는 R2 문서로 보완 |

디디쌤 시사점: 보상은 「돈과 같은 것」이 되는 순간 회계 · 환불 · 분쟁이 따라옵니다. 원장을 **삭제 없는 증감 줄**로 두고 환불 · 부정 · 정정을 모두 「반대 줄」로 처리하면, v41 수납 원장과 같은 방식으로 설명 · 감사가 됩니다.

## 5. 기관 유형별 기본 템플릿 8종

> **권장 정책안**입니다(D2). 기관은 모든 칸을 수정 · 보완하거나 제도를 쓰지 않을 수 있고, 어떤 유형이든 **제도 기본값은 끔**입니다. 숫자는 AI 초안이 기관 데이터(과정 수 · 학습량 · 예산)로 모의 계산해 조정합니다. 「현금성」 = 장학 · 학원비 차감 · 쿠폰. 국비 지원 과정은 유형과 관계없이 3.7 차단이 적용됩니다.

| 유형(`org.type` · `ed`) | 단위 이름 | 켜진 규칙(기본 배점 · 한도) | 기준점 · 승인 | 보상 전환 · 인정 기록 | 만료 · 노출 | 금지 · 주의 |

## 6. 기존 대학 비교과 마일리지(`lms/q.js`)와의 통합 · 이관

### 6.1 원칙
- **비교과 프로그램의 마일리지 값 · 이수 판정은 지금처럼 `lms_q`가 원천**입니다(학교 「성장마루」 절차를 옮긴 것이라 바꾸지 않음).
- 새 원장은 「확정된 결과」만 받습니다: 프로그램이 **마감(closed)** 될 때 이수자마다 `noncredit_done` 적립 1줄(값 = `lms_q_application.mileage`).
- 마감 전 「예정」(`mileage_expected`)은 지금처럼 `lms_q`에서 계산해 학습자 화면에 「적립 예정」으로 보입니다(원장에 대기 줄을 만들지 않음 — 마감 반려 · 이수 수정이 잦아 줄이 흔들리는 것을 막음).

### 6.2 연결 방법
| 단계 | 내용 | 위치 |
|---|---|---|
| 수집 | `lms_q_program.status`가 `closed`로 바뀔 때 DB 트리거가 `mil_emit('noncredit_done', …)`를 부름. 멱등 키 `lmsq:<program_id>:<member_no>` | `service/server/mileage/sql/20_mileage_hooks.sql`(Node · Java 공용 SQL) |
| 역량 | 역량 레이더(역량별 마일리지 배분)는 `lms_q` 그대로. 원장은 총량만 | `knq-learner.js` 변경 없음 |
| 학습자 화면 | 마일리지 모듈이 켜진 기관은 비교과 화면의 「확정 마일리지」 숫자를 누르면 「내 마일리지」로 이동. 숫자는 원장 잔액이 아니라 「비교과 확정 적립 합계」로 표기(사용 · 정산과 섞이지 않게) | `lscn-univ-lms.js` 또는 `knq-learner.js` 확장(시나리오 범위 확인) |
| 스튜디오 | 비교과 CSV · 이수증 · 운영계획서는 그대로 | 변경 없음 |
| 장학 정산 | 정산은 원장 잔액(비교과 + 기타 적립) 기준. 학교가 「비교과만」을 원하면 정산 조건에 `trigger in ('noncredit_done')` | 04 §5.1 정산 |

### 6.3 이관(이미 마감된 비교과)
1. 미리보기: 마감된 프로그램 × 이수자 수 · 합계 P를 보여 줍니다(`POST /api/mileage/import-q` `dryRun:true`).
2. 확인: 같은 멱등 키로 적립 줄을 만들고, 적립일 = 프로그램 마감일, 유효기간 = 기관 소멸 정책(마감일 기준으로 이미 지난 것은 소멸 처리할지 운영자가 선택).
3. 검증: `lms_q` 합계(학생별 `mileage` 합, closed만) = 원장 `noncredit_done` 합계를 학생별로 대조해 0건 차이를 확인합니다.
4. 데모 모드: `S.lms.q` → `S.mile` 같은 규칙으로 이관(브라우저 엔진).

### 6.4 충돌 · 주의
| 항목 | 처리 |
|---|---|
| `extra_mileage`(0~1000 수동 가산) | 원장 적립 1줄에 합쳐 들어가고, 근거에 「추가 마일리지 n」 표시. 대학은 운영자 지급(`manual`) 규칙을 따로 켜지 않아도 됨 |
| 마감 후 정정 | `lms_q`는 마감 후 수정 불가(`unlocked`). 정정이 필요하면 원장 「조정」 줄로만 |
| 학번 | `member_no` = 학습자 `sid`(확인: `knq-learner.js` 14행 `me()` = `LR.me.sid`) |
| 용어 | 비교과의 「마일리지」와 새 원장 「마일리지」가 같은 단어 → 학습자 화면에서 「비교과 마일리지(적립 근거)」 · 「내 마일리지(잔액)」로 구분 |

디디쌤 시사점: 대학 영업에서 「이미 쓰는 비교과 마일리지를 버리지 않고 장학 정산까지 이어진다」는 것이 설득 포인트입니다. 원천은 그대로 두고 확정분만 원장에 넣어 학교 절차를 건드리지 않습니다.

## 7. 부정 방지 · 동기 설계 원칙

### 7.1 부정 의심 규칙(스튜디오 「부정 의심」 탭)
| 의심 유형 | 탐지 | 기본 처리 |
|---|---|---|
| 몰아 쌓기(속도) | 1시간 안 같은 학습자 적립 n건 초과, 차시 완료 간격이 영상 길이보다 짧음(C 사건) | 이후 적립 보류 + 알림 |
| 상한 반복 도달 | 하루 상한을 7일 연속 꽉 채움 | 표시만(보류 없음) |
| 다계정 · 추천 남용 | 같은 기기 · IP에서 여러 계정 가입 후 서로 추천, 피추천인이 지급 직후 탈퇴 | 추천 적립 보류 |
| 재응시 농사 | 같은 시험 반복 응시로 구간 상승 시도 | 규칙상 시험마다 1회라 지급 안 됨, 시도 수만 표시 |
| 운영자 지급 이상 | 직원 1명이 하루 기준 이상 지급, 직원 본인 · 가족 계정(같은 연락처 해시) 지급 | 대표 승인 필요 · 본인 계정 차단 |
| 후기 남발 | 짧은 · 복사 후기 | 규칙 조건(글자 수 · 게시 유지)으로 지급 안 됨 |

탐지 근거는 개인정보 없이(기기 지문 해시 · IP 앞자리 · 사건 ID) 남기고, **자동 취소는 하지 않습니다**. 보류 → 운영자 확정 → 취소 순서입니다. 직훈 기관은 기존 HRD-Net 부정훈련 의심(여러 IP 접속 · 하루 학습시간 초과)과 같은 화면에서 봅니다.

### 7.3 공개 순위 · 감점 켜기 절차 (D3)
| 단계 | 내용 |

| 기본값 | 미성년 대상 기관(`k12`, 학습자 중 만 14세 미만 · 미성년 표시가 있는 기관)은 공개 순위 · 감점 **끔**. 그 밖의 기관도 권장 끔 |
| ① 켜기 시도 | 설정 › 순위 · 감점에서 스위치를 켜면 바로 적용하지 않고 「영향 안내」 시트를 엽니다 |
| ② 영향 안내 | 연구 요약(합니다체, 출처 표기): 미성년 공개 순위 · 감점 노출의 수치심 · 순응 중심 · 하위권 고착 우려(R1 §2 ClassDojo 비판), 예상된 보상과 내재 동기 감소(Deci 외 1999), 전체 상위 리더보드의 중하위권 이탈(R1 §5 Deloitte). 대안 제안: 근접 10명 · 주간 리셋 · 별명 표시 · 감점 대신 「적립 없음」 |
| ③ 범위 선택 | 공개 범위(근접 10명 / 반 · 기수 / 전체), 표시 이름(별명 · 이니셜 · 실명), 감점 사유 목록 · 1회 최대 감점 · 하루 상한, 대상(과정 · 반) |
| ④ 운영자 확인 | 「위 안내를 읽었고 기관 책임으로 켭니다」 확인 + 사유 입력(필수). k12는 학부모 공지 문구 초안을 함께 생성 |
| ⑤ 변경 이력 | 켠 사람 · 시각 · 사유 · 범위 · 전후 값을 감사 기록(`mileage.rank_penalty`)에 남기고 「설정 › 변경 이력」에 표시. 끌 때도 기록 |
| ⑥ 사후 점검 | 켠 뒤 30일 · 90일에 AI 정책 점검이 하위 구간 학습자 참여 변화를 집계로 보여 주고 유지 · 끄기를 제안(개인 단위 노출 없음) |

감점은 원장에 `kind 'penalty'` 음수 줄로 남고(사유 필수, 학습자에게 사유 표시), 이의 신청은 요청함으로 받습니다. 국비 과정(3.7)에도 감점은 적용될 수 있으나 금전성 보상과는 무관합니다.

디디쌤 시사점: 「포인트로 붙잡기」가 아니라 「학습의 흔적이 보이게」가 목표입니다. 상한 · 마일스톤 · 자기 비교를 기본값으로 고정해 두면 교육기관 의사결정자의 부담(사행성 · 과열 우려)을 줄일 수 있습니다.

### 10.2 남은 결정
1. **포인트 표기**: 권장 정책안의 기본을 「점수형(원 환산 표시 안 함)」으로 두고, 학원비 차감 · 1P=1원 장학을 고른 기관만 원 가치를 보이게 할지.

3. **국비 표시 기본 켬 범위**: 직훈(`voc`) · 고용노동부 규정 프로필 기관만 새 과정 기본 켬으로 할지, 평생교육원 · 기업(사업주 훈련)까지 넓힐지(R2 조문 확인 후 확정 권장).
