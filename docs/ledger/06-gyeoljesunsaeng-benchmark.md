# v41 통합 매출 · 수납 — 결제선생(PaySsam) 벤치마크와 연동 방안

대표님 지시(2026-11-14 02:44): 「학원 결제는 결제선생을 가장 많이 써. 해당 부분을 벤치마크해 줘.」 「데스크 결제의 경우 연동이 되어 있어야 돼.」
조사일: 2026-11-14. 선행 문서: `03-pg-benchmark.md`(PgAdapter), `04-van-offline.md`(데스크 어댑터), `05-academy-crm-benchmark.md`(F 항목).
표기: **[확인]** = 아래 출처 URL에서 직접 확인 · **[확인 필요]** = 공개 자료에서 확인하지 못함(추측하지 않음). 「가장 많이 쓴다」는 대표님 현장 인식이며, 시장점유율 공개 수치는 확인하지 못했다. 단, 2023년 기사에 가맹점 약 4만 1천 곳 · 교육 업종 80~85%로 적혀 있다(S4).

## 0. 요약

1. 결제선생은 **학원 CRM이 아니라 「모바일 청구서 결제 레이어」** 다. 운영사는 **페이민트(주)** [확인]. 학원이 청구서를 알림톡으로 보내면 학부모가 앱 설치 · 가입 없이 결제하고, 정산은 PG가 아닌 **카드사가 가맹점에 직접** 한다 [확인](S2, S4).
2. **파트너 API가 공개되어 있다**(개발자센터 정식 오픈 2026-05-13, V2) [확인](S6). 학원 관리 프로그램이 청구서 발송 · 수납 동기화 · 취소 · 현금영수증을 API로 붙이는 구조다. 맥가이 · 모두출첵 · 마음주의 등 국내 학원 · 매장 프로그램이 이미 연동 중이다 [확인](S9~S12). **파트너 계약 조건 · 수수료 · 단가는 비공개 → 페이민트 문의 필요.**
3. 결제선생 자체에는 **카드 단말이 없다.** 데스크에서 쓰는 방법은 ① 청구서 링크 · QR을 폰으로 결제 ② 단말 결제를 「현장 수납」으로 기록 정도로 보인다. **데스크 카드 단말 연동은 결제선생이 해결해 주지 않는다** → 04 문서의 VAN 연동이 별도로 필요하다.
4. **추천 = (c) 둘 다 지원.** 1차는 「결제선생 어댑터(`payssam`)」 + 수기 기록 + 데스크 로컬 에이전트 1종, 자체 PG(토스) 경로는 03 설계대로 유지. 근거 §3.
5. 대표님 결정 3건(§6).

## 1. 결제선생 기능 · 흐름

### 1-1. 서비스 구조

| 항목 | 내용 | 출처 |
|---|---|---|
| 운영사 | 페이민트(주). 출결 서비스 「출결선생」(체크앱)도 같은 회사 | S4, S13 |
| 성격 | 학원 · 병원 · 출장서비스 등 오프라인 사업장의 **비대면 청구서 결제**. 별도 단말기 불필요 | S1 |
| 결제 구조 | PG를 거치지 않고 카드사와 협의해 **오프라인 승인** 구조. 페이민트는 인증 담당, **정산은 카드사가 직접** | S4(2023 기사) |
| 규모 | 누적 가맹점 약 4만 1천(2023-07), 교육 업종 80~85%(기사 내 표기 불일치). 최신 수치 [확인 필요] | S4, S5 |
| 매니저앱 | 안드로이드 10만+ 다운로드, 2026-11-06 업데이트(「나눠서 결제」 · 「카드 결제 정산정보 확인」 신기능 소개) | S14 |
| 고객센터 | 채팅 전용(전화 없음), 월~목 09:30~18:00, 금 09:30~13:00, 주말 · 공휴일 휴무 | S3 |

### 1-2. 흐름 — 원장(학원) 관점

1. **가입 · 가맹**: 사업장(학원 · 교습소) 정보 입력 → 인허가증 · 매장 사진(간판 · 입구 · 내부 · 취급품목) 제출 → 가맹비 결제 → 심사 → 「심사완료」 알림톡 [확인](S10 모두출첵 안내). 심사 기간: 이미 카드가맹점이면 영업일 1일 이내, 아니면 3~5일 이상(S11 맥가이, S12 마음주의). **카드사 등록 최초 1회 3만원 실비**는 마음주의 문서에만 있음(S12) → 결제선생 공식 수치 [확인 필요].
2. **청구서 작성**: 학생 이름 · 보호자 휴대폰 · 금액 · 청구 사유 입력, 연락처 가져오기, **자동 파기일 지정**(마감일 24시, 연동 프로그램에서는 1~30일) [확인](S14, S11).
3. **정기 청구**: 매니저앱 「정기예약」으로 발송 횟수 최대 36회(앱 리뷰 답변 기준) [확인](S14). API에는 정기 청구 기능이 없고, **파트너가 매월 청구서 발송 API를 직접 호출**해야 한다(구독 취소 = 다음 결제일에 발송 안 함) [확인](S7).
4. **수납 확인**: 결제 완료 시 매니저앱 푸시, 발송 · 수납 내역(날짜 · 상태별), 매출보고서(결제수단 · 수납유형별 조회 · 다운로드) [확인](S14, S15).
5. **미납 대응**: 상세 화면에서 **재발송**(같은 청구서로 알림톡 새로 발송, 쌤포인트 차감) · 파기 · 결제취소 [확인](S14, S8). **미납자에게 일정 주기로 자동 독촉하는 기능은 확인하지 못함 [확인 필요]** (맥가이 · 클래스업 등 연동 프로그램 쪽에서 「미납 목록 → 일괄 발송」으로 제공 — S11).
6. **취소 · 환불**: 결제 대기 건은 파기, 결제 완료 건은 「결제취소」 → 환불 처리, 학부모에게 취소 알림톡 발송 [확인](S11 맥가이). 보호자 안내문에는 「환불은 영업일 1~3일 소요」, **「학원이 취소할 수 있는 것은 전액뿐」** 이라고 적혀 있다 [확인](S3). 반면 API V2 「나눠서 결제」 문서에는 **결제 건(`paymentId`)별 부분 취소**가 있다 [확인](S16). → 부분 환불은 「분할 결제로 낸 건 단위」까지만 가능하고, **임의 금액 부분환불(학원법 반환 계산액)은 확인되지 않음 [확인 필요]**.
7. **현금영수증**: 매니저에서 단건 · 다건 발급, API는 발행 · 취소 · 조회(`/cash-receipt/issue·cancel·read`) [확인](S15, S17). 보호자가 직접 발급은 불가, 현금 · 계좌이체 건은 학원에 요청. 네이버페이 · 카카오페이 머니 · 지역화폐 결제분은 대상 아님 [확인](S3).
8. **정산**: 보통 **D+2~3 영업일**(카드사별 상이, 주말 · 공휴일 제외), 가맹점이 내는 비용은 **카드사 결제수수료 + 청구서 발송비** 뿐이라고 설명 [확인](S1). **수수료율은 공개 페이지에 없다** [확인 필요]. 가맹점은 카드사에 결제수수료를 낸다(「오프라인 카드 리더기와 동일한 수수료, PG 추가 수수료 없음」 — 모두출첵 안내, S10).
9. **발송비**: 선불 포인트 「쌤포인트」(카드 충전, 계좌이체는 최소 50만원) 차감 [확인](S18). 결제선생 공식 건당 단가는 미공개. 참고 수치: 2023년 기사 55원/건(S4), 연동 프로그램 재판매가는 70포인트(맥가이, S11) · 3크레딧(마음주의, S12)로 **재판매 마진이 붙는 구조**.

## 2. 연동 가능 여부 — 파트너 API 사실관계

| 항목 | 내용 | 출처 |
|---|---|---|
| 공개 여부 | 개발자센터 공개(V2 정식 오픈 2026-05-13, V1 병존). 기술지원 메일 공개 | S6, S5 |
| 대상 | 학원 관리 프로그램 · 예약 서비스 · 병원 · 출장서비스 등 **파트너 플랫폼** | S5 |
| 구조 | 파트너 계약 → **하위사업장** 등록(가맹점이 결제선생에 사업장으로 가입 + 파트너 하위로 연결). 소량은 메일 수동 연결, 대량은 하위사업장 등록 API | S19 |
| 인증 | `apiKey` + `member`(사용자 코드) + `merchant`(매장 코드), 요청마다 SHA-256 `hash`(`billId,price` 등) | S20 |
| 발송 | `POST /bill`(`sendType` = `TALK`: 알림톡 발송 / `URL`: 단축 URL만 응답), 필수: `billId`(중복 불가, 1~20자) · 사유 · 금액 · 고객명 · 전화 · `callbackUrl` · `hash`. `expireDt` 유효기간(당일 24시) | S20 |
| 재발송 · 파기 | 같은 `billId` 재발송(쌤포인트 차감), 미결제만 파기. 결제 완료는 취소 API | S21 |
| 승인 동기화 | `callbackUrl`로 성공 건만 전달, `code:"0000"` 응답 필수, **실패 시 승인일시 기준 24시간 동안 1시간마다 재전송**, 중복 수신 가능 → `paymentId` 멱등 처리 | S8, S6, S16 |
| 결제 수단 값 | `CARD_VAN` · `KEYIN` · `OFFLINE_CARD` · `OFFLINE_CASH`(현금영수증 필드 동반) | S8 |
| 분할 | 한 청구서에 여러 결제, 건별 부분취소, 승인 동기화 최대 6회(**V2 전용**) | S16 |
| 현금영수증 | 발행 · 취소 · 조회 API | S17 |
| 쌤포인트 | 잔액 조회 API. 소진 대상은 파트너 일관관리(재판매형) 또는 하위사업장 개별(기능제공형) 중 선택 | S18 |
| 검수 | 테스트 거래 BILL-ID(승인 · 취소 · 파기 · 조회 · 동기화)를 기술지원에 회신 → 운영 키 발급. 기간 [확인 필요]. **테스트 환경은 일부 카드사만 실결제 가능**(현대 · 하나 · 신한 가능) | S22, S7 |
| 샌드박스 | `https://sandbox.paymint.co.kr/partner`(V2), 운영 도메인은 검수 후 제공. IP 허용 목록 공개 | S23 |
| **미확인** | 파트너 계약 조건 · 자격 · 수수료 배분 · 계약 기간 · 검수 기간 · 제휴 카드사 수수료율 · 단가표 · 가상계좌 지원 · 임의 금액 부분취소 | — |

## 4. 데스크 결제 「연동 필수」 반영 — 1차 구체안

결제선생 · 04 문서 기준 사실: 결제선생에는 단말 연동 기능이 없고(S1 「단말기 불필요」), API 수단 값에 `OFFLINE_CARD` · `OFFLINE_CASH`가 존재하나 **어떤 경로로 만들어지는지는 공개 문서에 없다 [확인 필요]**. 04 문서는 단말 직접 제어 표준이 없고 VAN별 프로그램 연동이 필요하다고 정리했다(KSNET KSCAT 선례: 클래스업, 토스 플러그인 SDK: NICE VAN 사용).

**1차 구체안(두 갈래를 같은 「수납 요청」 화면에서 제공):**

| 구분 | 방식 | 필요한 것 | 확인 수준 |
|---|---|---|---|
| ① 단말 있는 학원 | **데스크 PC 로컬 에이전트 + VAN 프로그램**: 04 §4-2 흐름. 1차 VAN은 **KSNET(KSCAT)** 기준(PC 설치 프로그램 + USB 암호화 리더기 · 서명패드, 선례 클래스업). 단말 모델은 KSNET 호환 목록의 **탁상형 리더기 + 서명패드** | KSNET 대리점과 **개발 규격 · SDK 제공 협약**, 호환 단말 목록 | 선례만 확인. 규격 제공 · 부분취소 **[확인 필요]**. 단말 모델명은 확정 불가(추측 금지) |
| ② 단말 없는 · 신규 학원 | **데스크에서 결제선생 URL 청구서 → QR 표시 → 학부모 폰으로 결제**. `sendType=URL`이 단축 URL(`shortUrl`)을 돌려주므로 단말 없이 현장 결제 가능 | 결제선생 파트너 계약 | **[확인]**(S20). 단 URL 방식 + 자동결제 시 `phone`에 실제 번호를 넣으면 **다른 고객 카드로 자동결제될 수 있어** 고유 고객 식별자를 쓸 것(S21) |
| ③ 공통 안전망 | **수기 기록 모드** + 일 마감 대사(04 §4-3, §4-5) | 없음 | 기존 설계 |

원장 연동 규칙: 수단별 결과를 **하나의 `receipt` 형식**으로 기록(04 §4-6). 데스크 카드(①)는 결제선생을 거치지 않으므로 결제선생 쪽 수납 상태와 별개다. **같은 청구 건을 학부모 링크와 데스크 단말로 이중 결제하지 않도록**, 데스크 수납 시작 시 해당 청구서의 미결제 결제선생 청구서를 **파기 API로 먼저 파기**(결제 완료 건은 파기 불가이므로 UI에서 차단)하는 규칙을 둔다.

필요한 제휴 정리: (1) KSNET 또는 NICE VAN 1곳 규격 협약 (2) 결제선생(페이민트) 파트너 계약 (3) 데스크 PC 설치 환경(Windows 가정 [확인 필요]).

## 5. 디디쌤 수납 화면이 결제선생보다 쉬워야 할 지점

결제선생 매니저는 「이름 · 번호 · 금액 · 사유 입력 → 발송」 중심이며, 학생 · 반 · 수강료 구조는 별도 프로그램(결제선생 자체 학생 · 클래스 메뉴 또는 연동 프로그램)에 있다 [확인](S15 가이드 목차). 디디쌤은 원장 데이터가 이미 있으므로 다음에서 앞서야 한다.

1. **입력 없는 청구**: 반 · 수강 정보에서 금액 · 사유 자동 생성(결제선생은 직접 입력). 형제 · 할인 · 교재비는 청구 전에 합산해 보여 준다.
2. **발송 전 한 화면 미리보기**: 학부모가 받을 알림톡 · 결제 화면 · 마감일 · 금액을 보고 일괄 발송.
3. **한 화면 상태**: 발송됨 · 열람 · 결제 · 만료 · 취소를 하나의 목록에(결제선생은 콜백이 성공만 오고 매니저 사이트 조작이 반영되지 않음 → 디디쌤은 조회 폴링으로 항상 일치).
4. **미납 독촉 규칙 설정**: 「마감 D+1 자동 재발송, 최대 N회」 등 규칙형. 재발송 시 발송비가 든다는 안내 표시(결제선생은 수동 재발송).
5. **수납 수단 자동 분기**: 「카드(단말) · 링크 · 현금 · 계좌」를 한 버튼에서 선택하고, 현금 선택 시 현금영수증 발급 여부를 같은 흐름에서 묻는다.
6. **환불 계산 연동**: 학원법 반환 기준 계산액을 제시하고 전액 · 부분을 자동 선택(결제선생은 전액 취소 중심, 임의 금액 [확인 필요]). 02 문서 환불 규칙과 연결.
7. **이중 결제 방지**: 데스크 수납 시 미결제 링크 청구서 자동 파기, 같은 학생 같은 달 중복 청구 경고.
8. **보호자 화면 일관**: 결제선생 알림톡 흐름을 쓰는 기관에서도 영수증 · 납입확인서는 디디쌤 화면에서 조회.
9. **연결 과정 단순화**: 「결제선생 연결하기」 버튼 하나로 가입 · 심사 상태 · 기존 계정 연결을 안내(서류 목록 · 예상 기간 표시). 심사 중에는 수기 기록으로 즉시 사용.
