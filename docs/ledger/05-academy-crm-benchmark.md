관찰 요약
1. **청구서 발행 · 수납 방식 · 미납 안내는 모든 서비스의 기본기**다. 차별은 결제 수단(키오스크 · 단말 · 모바일 링크 · 지역화폐)의 폭에서 난다.
2. **환불은 「기존 결제 수단으로 취소」 수준**이다. 학원법 교습비 반환 기준 자동 계산은 조사한 6곳 모두 공개 페이지에서 확인되지 않았다 → **디디쌤의 차별화 여지가 가장 큰 영역**이다(단, 법령 근거 확인이 선행 조건).
3. **할인은 정책 등록이 아니라 청구 시점 수작업**인 곳이 있다(클래스업은 매월 재설정). 형제 · 다과목 · 장기 자동 적용은 공개 정보로 확인되지 않았다.
4. **요금 구조는 「소프트웨어 무료 + 메시지 · 결제 · 키오스크로 과금」** 방향이다(클래스업 100명까지 0원, 학원조아 문자 건당). 디디쌤 요금 설계(`docs/ledger` 외 `didisam-pricing`)와 충돌하지 않게 학원 구간은 별도 검토가 필요하다.
5. **이전(마이그레이션)을 영업 무기로 쓴다**: 클래스업은 기존 프로그램이나 엑셀 명단의 학생 · 수업 데이터를 옮겨 주며 예시 소요 약 15분, 가입비 · 세팅비 · 약정 없음을 내세운다(https://classup.io/).

## 4. 따라잡을 것 · 차별화할 것 · 이전 요구

### 4-1. 반드시 따라잡을 것(없으면 영업에서 탈락)
1. 실결제 연동: 보호자 링크(모바일) 결제 + 현장 카드 결제 기록의 결제사 연동(수납이 「입력 장부」에 머무르지 않게).
2. 알림톡 · 문자 **실발송**(청구 · 마감 전 · 미납 · 출결). 경쟁사는 알림톡을 건당 단가로 이미 운영(클래스업 9원).
3. 현금영수증 발급 흐름(현금 수납 시 발급 여부 확인 → 번호 기록 → 조회). 세금계산서는 안내 수준 유지 가능.
4. 환불 기능 자체(환불 줄 · 결제 수단별 환불 경로). 「기존 결제 수단으로만 환불」 규칙은 경쟁사 공통이므로 같은 규칙 채택.
5. 청구서 자동 발행의 서버 실행(운영자가 열어야 도는 구조 해소) + 일할 · 회차 청구.
6. 보호자 앱의 청구서 확인 · 결제(실서버 보호자 계정 연결).
7. 미납 상태 노출: 원생 상세 · 출결 화면에서 미납 표시(키오스크는 2차).

### 4-2. 차별화할 것
| 차별점 | 경쟁 공백(근거) | 디디쌤 방향 |
|---|---|---|
| **학원법 반환 기준 자동 계산 + 직원 확정 + 근거 줄** | 6곳 모두 자동 계산 미확인. 클래스업은 결제 수단 환불만 | 시설 환불(`fac/calc.js`)의 「자동 금액 → 직원 확정 → 사유 기록」 방식 재사용. **법령 원문 확인 후 확정**(`01-scenario.md` §7-5) |
| **형제 · 다과목 · 장기 할인의 정책 자동 적용** | 클래스업은 매월 수동 재설정 | 이미 있는 할인 정책 + 형제 자동 연결을 청구 생성에 자동 반영, 청구 안 음수 줄로 근거 보존 |
| **AI 비서(AI SAM)로 수납 업무** | 조사 범위에서 AI 비서형 수납 확인 못함 | 「이번 달 수강료 발생」 「○○ 10만원 카드 수납」 「미납 알림 등록」은 이미 SAM 명령. 환불 계산 · 월 마감 요약 · 미수 사유 추천으로 확대 |
| **학습 연계 청구** | 조사 범위에서 출결 · 성적과 청구 연계 확인 못함 | 퇴원 · 휴원 · 결석 · 보강 기록이 청구에 반영(일할 · 회차 차감 근거), 성적 · 학습 데이터와 같은 원생 화면 |
| **통합 원장** | 조아는 다중 사업자 매출 구분, 나머지는 학원 수납만 | 학원 수강료 · 교재 · 시설 · 성인 강좌를 한 원장에서(`01-scenario.md` §2) |
| 개인정보 최소 원칙 | 조사 페이지에 별도 언급 없음 | 원장에 현금영수증 번호 · 카드번호 미보관(`01` §2-3) |

### 4-3. 마이그레이션(엑셀 가져오기) 요구
- 경쟁 기준: 클래스업은 「기존 프로그램 · 엑셀 명단 이전」을 서비스로 제공(약 15분, 약정 없음). 학원조아는 엑셀 다운로드 중심(내보내기). 가져오기 기능 상세는 6곳 모두 공개 확인 불가 → **디디쌤이 셀프 가져오기를 제대로 만들면 격차가 아니라 강점이 된다.**
- 현재: 원생 CSV · xlsx 일괄 등록(최대 건수 제한, 양식 7열: 이름 · 학교 · 학년 · 원생 연락처 · 보호자 이름 · 보호자 연락처 · 수업, `scn-k12.js:115~120`). **청구 · 수납 이력 가져오기는 없음.**
- 요구사항(1차):
  1. 원생 + 반 + 보호자 가져오기(기존 유지), 형제 연결 후보 자동 제안.
  2. **미납 잔액(기초 미수) 가져오기**: 원생 · 청구 월 · 항목 · 금액 · 이미 낸 금액. 전환 시점 이전 이력은 요약 1줄(이월 잔액)로 시작 가능.
  3. 과거 수납 이력(최근 12개월) 가져오기: 납부일 · 금액 · 수단 · 품목. 중복 방지(원생 · 월 · 반 키).
  4. 오류 행 미리보기 후 반영(가져오기 전 검증), 되돌리기(일괄 취소) 가능.
  5. 경쟁사 내보내기 양식(조아 · 클래스업 엑셀) 열 이름 매핑 프리셋은 2차.
  6. 개인정보: 업로드 원본은 반영 후 삭제, 감사 로그에 건수만 기록.
