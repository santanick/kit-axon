# 디디쌤 개인정보 내부 관리계획

| 항목 | 내용 |
|---|---|
| 문서 번호 | SANTA-PRV-IMP-001 |
| 판 | 제1판(초안) · 2026-11-25 |
| 근거 | 「개인정보의 안전성 확보조치 기준」(개인정보보호위원회고시 제2026-9호, 2026. 7. 1. 시행) 제4조 · 「개인정보 보호법」 제29조 |
| 적용 범위 | 산타(주)가 운영하는 디디쌤(DIDISAM) Ver2 — 디디쌤 스튜디오(운영자 화면) · 학습자 사이트 · 서버(`service/server` Node, `service-egov` Java) · DB(Cloud SQL PostgreSQL) · 백업 |
| 적용 대상 | 산타 임직원 · 산타 관리자 계정, 고객 기관의 운영자(정운영자 owner · 부운영자 sub · 교수자 teacher), 개발 · 운영 위탁 인력 |

> 고시 제4조제1항 단서(1만 명 미만 처리 소상공인 등 생략)는 산타에 해당하지 않으므로 이 계획을 수립 · 시행합니다.
> 산타의 지위: 고객 기관 학습자 개인정보는 **기관이 개인정보처리자, 산타가 수탁자**입니다. 운영자 계정 정보(이메일 · 접속기록)와 산타 직접 판매 회원은 **산타가 개인정보처리자**입니다. 이 계획은 두 지위 모두에 적용합니다.

---

## 제1장 총칙

### 제1조(목적)
이 계획은 디디쌤이 처리하는 개인정보가 분실 · 도난 · 유출 · 위조 · 변조 또는 훼손되지 않도록 산타가 지켜야 할 관리적 · 기술적 · 물리적 안전조치를 정합니다.

### 제2조(용어)
- **개인정보처리시스템**: 디디쌤 스튜디오 · 학습자 사이트 · 서버 API · DB · 백업 저장소.
- **개인정보취급자**: 개인정보처리시스템에 접속해 개인정보를 처리하는 사람. 디디쌤에서는 운영자(owner · sub · teacher)와 산타 관리자(`SANTA_ADMIN_EMAILS`)를 말합니다. 학습자(정보주체)는 취급자가 아닙니다.
- **2단계 인증**: 비밀번호 확인 뒤 추가로 거치는 인증 단계(이메일 인증번호 또는 인증 앱 일회용 비밀번호).
- **접속기록**: 취급자의 식별자 · 접속 일시 · 접속지 정보(IP) · 처리한 정보주체 정보 · 수행 업무를 담은 기록(`pii.access_log`, `audit_log`).

## 제2장 고시 제4조제1항 각 호 사항

### 1. 개인정보 보호 조직의 구성 및 운영 (제1호)
| 역할 | 담당 | 주요 업무 |
|---|---|---|
| 개인정보 보호책임자(CPO) | 대표이사 | 계획 승인, 연 1회 이행 점검, 유출 사고 최종 판단 · 신고 |
| 개인정보 보호담당자 | 부대표(강효운, 보안 담당 겸직) | 월간 접속기록 점검, 분기 권한 검토, 취약점 조치, 교육 운영 |
| 보안 운영(디디쌤 가디언) | 자동 보안 점검 도구 + 담당자 | 상시 취약점 탐지 · 수정 PR(사람 승인 병합), 긴급 차단 3종 |
| 부서 담당자 | 사업 · CX · 마케팅 각 1명 | 부서 내 개인정보 출력 · 내려받기 관리, 위탁사 관리 협조 |
- 회의: 분기 1회 보호 조직 회의(권한 검토 결과 · 점검 결과 · 사고 · 개정 사항). 회의록은 Drive 「Santa Agent/보안」에 보관합니다.

### 2. 개인정보 보호책임자의 자격요건 및 지정 (제2호)
- 「개인정보 보호법 시행령」 제32조에 따라 사업주 또는 대표자, 또는 임원(임원이 없으면 개인정보 처리 부서의 장)을 지정합니다. 산타는 **대표이사**를 지정합니다.
- 지정 · 변경 시 개인정보 처리방침에 성명 · 연락처를 공개하고 이 계획의 개정 이력에 기록합니다.

### 3. 보호책임자와 취급자의 역할 및 책임 (제3호)
- **보호책임자**: 처리 현황 조사 · 개선, 불만 처리, 유출 방지 체계 구축, 교육 계획 수립, 이 계획의 이행 점검(연 1회 이상, 제4조④).
- **보호담당자**: 접속기록 월 1회 점검, 권한 분기 검토, 내려받기 사유 확인, 취약점 조치 기록.
- **운영자(취급자)**: 1인 1계정 사용 · 공유 금지, 2단계 인증 사용, 업무 목적 외 열람 · 출력 금지, 원문 열람 시 목적 입력, 자리 비움 시 로그아웃.
- **개발자**: 개인정보 최소 수집 설계, 시큐어코딩(행안부 49개 보안약점 기준), 시험 데이터에 실제 개인정보 사용 금지, 로그 · 알림에 인증번호 · 비밀값 기록 금지(해시만).

### 4. 취급자 관리 · 감독 및 교육 (제4호, 제4조②)
| 구분 | 대상 | 내용 | 일정 · 방법 |
|---|---|---|---|
| 정기 교육 | 산타 전 임직원 | 개인정보 보호법 · 안전조치 기준, 이 계획, 유출 사고 사례 | 연 1회(매년 3월) · 온라인 1시간 + 이수 기록 |
| 역할 교육 | 개발 · 운영 인력 | 시큐어코딩, 비밀값 관리, 사고 대응 절차 | 연 1회 + 입사 시 |
| 운영자 안내 | 고객 기관 운영자 | 2단계 인증 등록, 원문 열람 규칙, 내려받기 규칙 | 기관 개통 시 사용자취급설명서 · 화면 안내 |
- 감독: 월간 접속기록 점검(8호)과 분기 권한 검토(5호) 결과로 목적 외 처리 여부를 확인합니다. 입사 · 퇴사 시 비밀유지 서약을 받습니다.

### 5. 접근 권한의 관리 (제5호, 고시 제5조)
- 권한은 업무에 필요한 최소 범위로 차등 부여합니다: 정운영자(owner) — 기관 전체 · 개인정보 원문 열람 · 보안 정책 변경, 부운영자(sub) — 운영 업무(원문 열람 불가, MCP 읽기만), 교수자(teacher) — 담당 강의 범위, 산타 관리자 — 요금제 · 기관 지원.
- 퇴직 · 업무 변경 시 **지체 없이**(당일) 권한을 변경 · 말소합니다.
- 권한 부여 · 변경 · 말소 내역(`role.*` · `member.*` 등 권한 관련 audit)은 **3년 이상** 보관합니다(고시 제5조③).
- **분기 1회 권한 검토**: 정운영자가 스튜디오 「권한 검토」 화면(`GET/POST /api/access-review`)에서 운영자 목록 · 역할 · 마지막 로그인을 확인하고 「검토 완료」를 기록합니다(audit `access.review`). 90일 이상 미사용 계정은 검토 시 정지 또는 삭제합니다.
- 계정은 취급자별로 발급하고 공유를 금지합니다(제5조④). 기관 공용 계정 생성은 허용하지 않습니다.
- 인증 실패: 운영자 · 학습자 모두 **같은 계정 15분 안 5회 실패 시 15분 잠금**(DB 기준, 모든 로그인 경로 — 이메일 · 간편 · 학번)(제5조⑥).
- 비밀번호: 2종 10자 또는 3종 8자 이상, scrypt 일방향 저장. 주기적 강제 변경은 두지 않습니다(안전조치 기준 안내서 FAQ 근거).

### 6. 접근통제 (제6호, 고시 제6조)
| 통제 | 기준 | 구현 |
|---|---|---|
| 외부 접속 2단계 인증(제6조②) | 운영자(owner · sub · teacher, 산타 관리자 포함)는 **로그인할 때마다** 비밀번호 뒤 2단계 인증 | 기본 **이메일 인증번호 6자리**(CSPRNG, 10분 유효, 5회 틀리면 무효, 1회용, 해시 저장). 본인이 **인증 앱(TOTP: RFC 6238 · SHA1 · 30초 · 6자리 · 앞뒤 1창 · 재사용 거절)**으로 바꿀 수 있음. 기관 정책 `org.sec.mfa` = `email`(기본) · `totp`(기관 전원 인증 앱 강제, 정운영자만 변경 · audit). 소셜 로그인 뒤에도 같은 2단계. 「이 기기 기억」 없음(접속 시마다). 학습자는 대상 아님 |
| 자동 접속 차단(제6조④) | 운영자 **유휴 60분**(기본), 기관이 **10~60분** 범위에서 선택(`org.sec.idleMin`) | 사용 중에는 자동 연장, 세션 최대 수명 **12시간**, 운영자 쿠키는 브라우저 세션 쿠키(브라우저를 닫으면 로그아웃, 자동 로그인 없음). 만료 **5분 전** 화면 안내 + 「계속 사용」. 재접속은 비밀번호 + 2단계 인증(최초 접속과 같은 수준) |
| 장시간 작업 예외 | 데이터 이관 · 점검 등 | 「작업 모드」: 사유와 시간(최대 240분)을 입력하면 audit 기록 후 적용, 끝나면 자동 원복 |
| 동시 접속 | 허용하되 알림 · 통제 | 로그인 시 다른 활성 세션이 있으면 화면 배너("다른 기기에서도 로그인되어 있습니다."). 계정 설정 「로그인 기기 · 세션」 목록 + 「다른 기기 모두 로그아웃」. 기관 선택 `org.sec.maxSessions`(0 = 제한 없음 기본, n이면 가장 오래된 세션 종료) |
| IP 제한 · 이상 탐지(제6조①) | 선택 적용 | `ADMIN_IPS` 허용 목록, 새 기기 · 대역 · 국가 로그인 알림 메일, 기관 선택 `org.sec.krOnly`(국외 IP 운영자 로그인 차단, 기본 꺼짐), IP 30회 · 이메일 8회/10분 속도 제한 |
| 학습자 세션 | 정보주체 — 제6조④ 의무 대상 아님, 서비스 기준으로 관리 | 「로그인 유지」 끔: 브라우저 세션 쿠키 + 서버 12시간. 켬: 마지막 사용 기준 30일 연장(최대 90일). 학번+접근코드 로그인도 같은 규칙 |
| 공개 · 유출 방지(제6조③) | 공유 설정 · 공개 URL 통제 | 테넌트 분리(RLS · FORCE RLS), 학습자 사이트 공개 범위 설정, 파일 공개 링크 점검(월간 점검 항목) |
| 업무용 모바일(제6조⑤) | 화면 잠금 · 비밀번호 | 산타 임직원 업무 휴대폰 화면 잠금 의무, 분실 시 즉시 보고 · 세션 원격 종료 |

> 이메일 인증번호가 고시의 「안전한 인증수단」에 포함되는지는 원문에 명시가 없습니다(안내서 예시: 인증서 · 보안토큰 · 일회용 비밀번호). 산타는 서버가 한 번만 쓰는 무작위 번호를 짧은 유효시간으로 발급하는 방식을 「일회용 비밀번호 등」으로 보고 기본값으로 쓰되, 고위험 기관(재학생 1만 명 이상 대학 · 공공 · 직업훈련)에는 `totp` 정책을 권고합니다. 개정 안내서(2026. 11.) 원문 확인 후 이 조항을 재검토합니다.

### 7. 개인정보의 암호화 조치 (제7호, 고시 제7조)
| 대상 | 방식 |
|---|---|
| 비밀번호 | scrypt 일방향 저장 |
| 세션 토큰 · 2단계 인증 티켓 · 인증번호 · 복구 코드 | SHA-256 해시만 저장(원문 미저장) |
| TOTP 비밀값 | 서버만 보관, `PII_KEY`로 암호화 |
| 학습자 개인정보 원문(이메일 · 이름 · 휴대폰) | `pii` 스키마에 분리 · 암호화 저장, 운영자 화면은 가린 값만 |
| 주민등록번호 · 카드 · 계좌번호 | **수집하지 않음**. 결제는 PG사 결제창에서 처리(카드 정보는 디디쌤에 저장되지 않음) |
| 전송 구간 | HTTPS(TLS 1.2 이상) + HSTS. DB 연결은 `DB_SSL_CA` 설정 시 서버 인증서 검증(`rejectUnauthorized: true`), Java는 JDBC `sslmode=verify-ca` |
| 취급자 PC 저장(내려받기) | 개인정보 포함 CSV는 기본 마스킹, 원문은 정운영자 + 사유 입력 시만 · audit `export`(건수 기록) |
| 키 관리 | `PII_KEY` 등 비밀값은 GCP Secret Manager 보관, 교체 절차는 `docs/security/secrets.md` |

### 8. 접속기록 보관 및 점검 (제8호, 고시 제8조)
- **기록 항목**: 식별자(운영자 ID) · 접속 일시 · **접속지 IP** · 처리한 정보주체(학습자 ID) · 수행 업무(열람 · 수정 · 내려받기 · 삭제 등) · 목적.
- **보관 기간**
  | 기록 | 기간 | 근거 |
  |---|---|---|
  | 개인정보 접속기록(`pii.access_log`) | **2년** | 고시 제8조①(기본 1년, 5만 명 이상 처리 등은 2년 — 고객 규모 합산 시 해당 가능성이 있어 2년으로 통일) |
  | 감사기록(`audit_log`) 일반 | **2년** | 위와 같음 |
  | 권한 부여 · 변경 · 말소 기록 | **3년** | 고시 제5조③ |
  | 결제 · 환불 기록 | 5년 | 전자상거래법 |
- 기관 삭제 시에도 로그는 연쇄 삭제하지 않고 보관 기간까지 유지한 뒤 일 1회 파기 작업으로 지웁니다.
- 위 · 변조 방지: `audit_log` 해시 체인 + 검증 API(`GET /api/audit/verify`), 앱 DB 역할은 로그 테이블에 select · insert만 허용합니다.
- **점검 주기: 월 1회**(매월 첫 영업일 기준 5영업일 안). 방법과 사후조치는 [access-log-review.md](access-log-review.md)를 따릅니다. 대량 내려받기(1회 1,000명 이상)는 사유를 확인하고, 사유가 없으면 해당 운영자 소명 → 권한 조정 → 필요 시 유출 사고 절차(14호)로 넘깁니다.

### 9. 악성프로그램 등 방지 (제9호, 고시 제9조)
- 임직원 PC는 백신 자동 업데이트(일 1회 이상)를 켭니다. 보안 업데이트 공지 시 즉시 적용합니다.
- 서버 의존성은 디디쌤 가디언이 상시 점검(npm · Maven 취약점, 컨테이너 이미지 스캔)하고, 긴급 패치는 SLA(README 6절)에 따라 적용합니다.
- 업로드 파일은 확장자 · MIME 검사, 실행 파일 차단.

### 10. 취약점 점검 (제10호)
- 상시: 디디쌤 가디언(Semgrep 기준선 · 의존성 · 비밀값 스캔), 배포 전 게이트.
- 정기: **연 1회 이상** KISA 2026 「Web Application 21항목」 점검([kisa-web-check.md](kisa-web-check.md)), 행안부 구현단계 보안약점 49개 대조([swdev49.md](swdev49.md)).
- ISMS-P 신청 전 외부 모의해킹 1회. 결과는 조치 완료까지 `security/findings/`에 기록합니다.

### 11. 물리적 안전조치 (제11호)
- 서버 · DB는 Google Cloud 서울 리전(물리 보안은 위탁사 인증 범위). 산타 사무실(부산 해운대 · 서울 성동구)에는 개인정보를 저장한 서버를 두지 않습니다.
- 개인정보가 담긴 종이 · 보조저장매체는 잠금장치가 있는 보관함에 보관하고, 반출은 보호담당자 승인 후 기록합니다.

### 12. 출력 · 복사 시 안전조치 (제12호, 고시 제12조)
- 출력(화면 · 인쇄 · 파일)은 용도를 특정하고 필요한 항목만 포함합니다.
- 개인정보 포함 CSV 내려받기: **사유 입력 필수**, 기본은 가린 값, 원문은 정운영자 + 사유. 건수와 사유를 audit `export`로 기록하고 월간 점검에서 확인합니다.
- 운영자 화면 목록은 닉네임 · 가린 이메일만 표시하며, 원문 열람은 목적 선택 후 기록됩니다.

### 13. 개인정보의 파기 (제13호, 고시 제13조)
| 대상 | 시점 | 방법 |
|---|---|---|
| 학습자 개인정보(원문) | 탈퇴 즉시 · 보유 목적 달성 시 | `pii` 스키마 행 삭제, 학습 기록은 가명(「탈퇴 회원」)으로만 보관 |
| 만 14세 미만 가입 미동의 | 7일 안 법정대리인 동의가 없으면 | 가입 정보 자동 파기 |
| 2단계 인증 티켓 · 인증번호 | 사용 즉시 또는 만료(티켓 5분 · 인증번호 10분) | 해시 행 삭제 |
| 접속기록 · 감사기록 | 보관 기간(2년/3년) 만료 | 일 1회 파기 작업 |
| 위탁 계약 종료 기관 | 계약 종료 후 기관 요청에 따라 반환 또는 30일 안 파기 | DB 삭제 + 파기 확인서 발급(로그는 보관 기간까지 유지) |
| 백업 | 보존 주기(Cloud SQL 자동 백업 · PITR) 경과 | 자동 만료 |
- 파기 내역(대상 · 건수 · 일시 · 담당)은 audit에 남깁니다.

### 14. 개인정보 유출사고 대응 계획 (제14호)
1. **인지(0시간)**: 탐지 경로(가디언 알림 · 월간 점검 · 신고) → 보호담당자가 즉시 보호책임자에게 보고.
2. **차단(즉시)**: 긴급 차단 3종(README 5절) — 해당 세션 · 키 폐기, 계정 잠금, 기능 차단.
3. **조사(24시간 안)**: 접속기록 · audit로 유출 범위(항목 · 인원 · 기관) 확정.
4. **통지 · 신고(72시간 안)**: 1천 명 이상 · 민감정보 · 해킹에 의한 유출 등 법정 요건 해당 시 개인정보보호위원회 · KISA 신고, 정보주체 통지. 수탁자로서는 **고객 기관에 지체 없이 통보**하고 기관의 통지 · 신고를 지원합니다.
5. **재발 방지**: 원인 분석 보고서, 수정 PR, 이 계획 개정 여부 검토.
- 연 1회 모의 훈련(테이블탑)을 실시합니다.

### 15. 위험 분석 및 관리 (제15호)
- 연 1회(매년 1월) 개인정보 흐름도 · 자산 목록을 갱신하고, 위협별 가능성 × 영향으로 위험을 평가합니다.
- 우선순위 공식과 조치 기한은 README 7절(가디언 우선순위)을 따르며, 수용 위험은 보호책임자가 서명으로 승인합니다.

### 16. 수탁자 관리 및 감독 (제16호)
| 수탁자 | 위탁 업무 | 국가 | 관리 |
|---|---|---|---|
| Google Cloud | 서버 · DB · 백업 호스팅 | 대한민국(서울 리전) | 표준 계약 · 보안 인증 확인(연 1회) |
| Anthropic, PBC | AI 기능 처리(개인정보를 가린 질문 글) | 미국(국외이전) | API 입력 학습 미사용 조건 확인, 처리방침 국외이전 고지 |
| 결제대행사(PG, 토스페이먼츠 등) | AI 사용량 충전 · 요금제 · 수강료 결제 처리 | 대한민국 | 카드 정보는 PG만 처리, 위탁 계약 · 처리방침 고지 |
| 메일 발송 서비스 | 인증번호 · 알림 메일 발송 | 계약 서비스에 따름 | 발송 내용 최소화(인증번호 외 개인정보 미포함) |
- 위탁 계약서에 목적 외 처리 금지, 재위탁 제한, 안전조치, 관리 · 감독, 손해배상을 명시하고 연 1회 이행 상황을 확인합니다.
- 산타가 수탁자인 경우: 고객 기관의 점검 요청(점검표 · 접속기록 · 취약점 점검 결과)에 응하고, 이 계획을 증빙으로 제공합니다.

### 17. 내부 관리계획의 수립 · 변경 및 승인 (제17호, 제4조③ · ④)
- 수립 · 변경: 보호담당자가 초안 작성 → 보호 조직 회의 검토 → **보호책임자 승인**으로 시행합니다.
- 법령 개정 · 서비스 구조 변경 · 사고 발생 등 **중요한 변경은 즉시 반영**하고 개정 이력을 남깁니다.
- **연 1회 이행 점검**: 보호책임자가 매년 12월 접근 권한 관리 · 접속기록 보관 및 점검 · 암호화 조치 등 이 계획 전체의 이행 실태를 점검하고 결과 보고서를 보관합니다(첫 점검 2026-12).
- 규정 수치(유휴 시간 · 잠금 횟수 · 보관 기간)를 바꾸면 이 문서 · `docs/security/README.md` · 서버 상수 · 시험을 함께 고칩니다.

### 18. 그 밖에 개인정보 보호를 위하여 필요한 사항 (제18호)
- **AI 기능**: 질문 글의 학번 · 연락처 등은 가린 뒤 전송, 기관이 AI 기능을 끄거나 국내 모델 경로를 선택할 수 있습니다. 고영향 AI 자가판정은 [ai-impact-assessment.md](ai-impact-assessment.md).
- **만 14세 미만**: 법정대리인(보호자) 동의 링크, 동의 기록 보관.
- **최소 수집**: 대학은 학번 · 학과만, 일반 기관은 로그인 수단 1개 · 닉네임만 필수.
- **교육부 학습지원 SW 필수기준** 대응: [moe-checklist.md](moe-checklist.md).
- **시험 환경 예외**: 서버 환경 `MFA_OFF=1`은 자동 시험 · 데모 전용이며 운영 환경에서는 설정하지 않습니다(배포 점검 항목).
