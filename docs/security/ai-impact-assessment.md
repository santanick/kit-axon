# 고영향 AI 자가판정 — 디디쌤 Ver2 (체크리스트 02)

디디쌤 Ver2의 AI 기능이 「인공지능 발전과 신뢰 기반 조성 등에 관한 법률」(인공지능기본법, 2026-01-22 시행)의 **고영향 인공지능**에 해당하는지 기능별로 자가판정하고, 기관 운영자가 스튜디오에서 최종 판단을 기록하는 기준입니다.

- 작성: 2026-11-24 · 보안 2차(수석 기획자) · 개정 시 이 문서와 `didisam/ulms.js`(`HIA_FN` · `HIA_Q` · `hiaSelf`), `tests/ui/hia.js`를 함께 수정합니다.
- 주의: 이 문서는 사업자 자가 검토 자료이며 법률 자문이 아닙니다. 시행령 · 고시 · 과학기술정보통신부 가이드라인 최신본으로 분기마다 다시 확인하고, 판단이 어려우면 법 제33조에 따라 과기정통부에 확인을 요청합니다.

## 1. 근거 조항(요지)
| 조항 | 요지 | 디디쌤 대응 |
|---|---|---|
| 제2조(정의) 고영향 인공지능 | 사람의 생명 · 신체 안전 · 기본권에 중대한 영향을 줄 우려가 있는 영역의 AI. 영역에 **채용 등 개인의 권리 · 의무에 중대한 영향을 주는 판단 · 평가**, **유아 · 초 · 중등교육의 학생 평가**가 포함됩니다 | 판정 질문 「채용」 · 「초중고」 · 「평가」 |
| 제31조(투명성) | 고영향 · 생성형 AI 이용 사실 사전 고지, 생성형 결과물 표시 | 체크리스트 01(AI 생성물 표시) — 보안전문가 담당 |
| 제33조(고영향 AI 확인) | 제공 전 고영향 해당 여부를 사업자가 검토, 필요하면 장관에게 확인 요청 | 이 문서 + 스튜디오 판단 기록 |
| 제34조(사업자 책무) | 위험관리 방안, 설명 방안, 이용자 보호 방안, 사람의 관리 · 감독, 조치 내용 문서 작성 · 보관 | 2절 「해당」일 때 준비 항목 |
| 제35조(영향평가) | 기본권 영향평가 노력 의무 | 공공 · 초중고 납품 시 권고 |

## 2. 판정 방법
질문 4개(예/아니오)로 자가판정하고, 사람이 최종 판단합니다.

| 질문 키 | 질문 |
|---|---|
| `eval` | 학생 평가 · 성적 · 수료 판정에 결과가 쓰입니까? |
| `hire` | 채용 · 선발 · 자격 부여 판단에 결과가 쓰입니까? |
| `k12` | 초 · 중 · 고(유아 포함) 학생에게 쓰입니까? |
| `auto` | 사람 확인 없이 결과가 그대로 확정 · 발송됩니까? |

| 자가판정 | 조건 | 최종 판단 기본값 |
|---|---|---|
| 해당 가능성 높음 | (채용 ∧ 자동 확정) 또는 (평가 ∧ 초중고 ∧ 자동 확정) | 해당(고영향) |
| 검토 필요 | 채용, 또는 (평가 ∧ 초중고), 또는 (평가 ∧ 자동 확정) | 조건부 비해당(사람 최종 확정 유지) |
| 해당 가능성 낮음 | 그 밖 | 비해당 |

- **최종 판단 3종**: 해당(고영향) · 조건부 비해당(사람 최종 확정 유지) · 비해당. 「조건부」는 AI가 초안만 만들고 사람이 확정하는 설계를 유지하는 조건으로 비해당이라는 뜻이며, 설계가 바뀌면 다시 판단합니다.
- **해당**이면 제34조 5개 항목(위험관리 · 설명 · 이용자 보호 · 사람 관리감독 · 문서 보관)을 준비하고 출시 전 대표님 승인을 받습니다.

## 3. 기능별 판정(산타 기본 판정 · 2026-11-24)
| 기능(키) | 쓰임 | 평가 | 채용 | 초중고 | 자동 확정 | 자가판정 | 산타 기본 판정 · 이유 |
|---|---|---|---|---|---|---|---|
| AI 튜터 · Q&A(`tutor`) | 학습자 질문 답변 | 아니오 | 아니오 | 기관 따라 | 아니오 | 낮음 | 비해당 — 평가 · 판단에 쓰이지 않음. 생성물 표시(01)만 적용 |
| 퀴즈 · 출제 · 추천(`quiz`) | 문제 초안 · 추천 | 아니오 | 아니오 | 기관 따라 | 아니오 | 낮음 | 비해당 — 문제는 교수자가 검토 후 게시 |
| 요약 · 번역 · 문서뷰어(`sum`) | 학습 보조 | 아니오 | 아니오 | 기관 따라 | 아니오 | 낮음 | 비해당 |
| 과제 · 서술형 채점 보조(`grade`) | 채점 초안 | **예** | 아니오 | 기관 따라 | 아니오 | 낮음 → 초중고면 **검토 필요** | **조건부 비해당** — 점수는 교수자가 확정(`human` 항목). 초중고 기관은 반드시 조건부로 기록 |
| 학습위기 예측(`risk`) | 상담 대상 추천 | 아니오 | 아니오 | 기관 따라 | 아니오 | 낮음 | 비해당 — 상담 권유에만 쓰고 불이익 처분에 쓰지 않음(쓰면 재판단) |
| 자동 자막 · 실시간 번역(`sub`) | 접근성 | 아니오 | 아니오 | 기관 따라 | 아니오 | 낮음 | 비해당 |
| AI 모의면접 · 면접 평가(`interview`) | 취업 면접 연습 | 아니오 | 아니오(연습용) | 아니오 | 아니오 | 낮음 | 비해당 — **기업이 실제 채용 선발에 쓰면 「채용 예」로 바꾸고 해당 여부 재판단** |
| 운영 AI SAM(`sam`) | 운영 자동화 | 아니오 | 아니오 | 아니오 | 아니오(승인 후 실행) | 낮음 | 비해당 — 2등급 이상 도구는 서버가 사람 확인 요구(체크리스트 09) |

기관 유형이 초중고(`k12`)이면 「초중고」 질문 기본값이 예로 시작합니다. 기관마다 쓰임이 다르므로 **기관별 판단은 스튜디오 기록이 원본**이고, 위 표는 산타 기본안입니다.

## 4. 스튜디오 기록 기능(구현 완료 · 최소 범위)
- 위치: 스튜디오 「AI 관리」 › 「AI기본법 · 거버넌스」 탭 › **고영향 AI 자가판정** 카드(`didisam/ulms.js`, 모든 기관 유형).
- 표: 기능 8개 × 질문 4개 체크 · 자가판정 태그 · 최종 판단(판단자 · 일시) · [판단 기록] 버튼.
- [판단 기록] → 창에서 최종 판단 3종 중 선택 + **사유 필수**(300자) → 저장 시 `S.lms.ai.hia[기능] = { q, final, note, by, at, basis }`, 이력 `hiaLog`(최근 100건, 질문 답 스냅숏 포함), 감사 기록(`고영향 AI 최종 판단 — …`).
- 질문 답이 판단 당시와 달라지면 「재판단 필요」로 표시되고 완료 수에서 빠집니다.
- 8개 기능이 모두 최신 판단이면 AI기본법 체크 목록의 `hia` 항목이 자동 체크됩니다(수동 체크 불가).
- 권한: 정운영자 · 관리자만 질문 변경 · 판단 기록(교수자는 메뉴 자체가 없고, 직접 호출도 거절).
- 증빙: [판단 기록 내보내기] CSV(일시 · 기능 · 질문 4개 · 자가판정 · 최종 판단 · 판단자 · 사유).
- 저장 위치는 기관 상태(`tenant_state`, 암호화 저장)입니다. 위 · 변조 방지는 감사 기록 해시 체인(SEC-0006, 개발자 2)에 기대며, 판단 기록 전용 서버 표는 두지 않았습니다(남은 것 참고).
- 시험: `flock /tmp/pw.lock node tests/ui/hia.js` (16항목).

## 5. 남은 것
- 판단 기록 전용 서버 API · 표(`/api/ai/impact`)는 만들지 않았습니다. 공공 · 초중고 납품에서 별도 제출 양식이 요구되면 Node · Java 함께 추가합니다(통합 채팅방).
- 「해당」 판정 기능이 생기면 제34조 문서 묶음(위험관리 · 설명 · 이용자 보호 · 관리감독 · 보관) 양식을 이 폴더에 추가합니다.
- 시행령 · 고시의 고영향 세부 기준 확정본이 나오면 2절 조건을 갱신합니다.
