# 접속기록 월간 점검 절차 (체크리스트 07 · 12 운영)

개인정보처리시스템 접속기록을 보관하고 매월 점검하는 절차입니다. 비밀값 목록 · 교체 주기 · 교체 절차(체크리스트 12)는 `docs/security/secrets.md`(개발자 2)가 원본이며, 이 문서는 월간 점검에서 **비밀값 스캔 결과를 확인하는 한 줄**만 다룹니다.

- 근거: 개인정보보호위원회 「개인정보의 안전성 확보조치 기준」 접속기록 보관 · 점검 조항(월 1회 이상 점검, 보관 1년 이상 — 정보주체 5만 명 이상 또는 고유식별 · 민감정보 처리 시 2년 이상, 개인정보 다운로드는 사유 확인). 고시 최신본으로 연 1회 확인합니다.
- 작성: 2026-11-24 · 보안 2차(수석 기획자).

## 1. 대상 기록과 보관
| 기록 | 위치 | 담는 것 | 위변조 방지 | 보관 |
|---|---|---|---|---|
| 개인정보 열람 · 수정 · 삭제 | `pii.access_log` | 기관(tid) · 일시 · 처리자(actor) · **접속 IP(가디언 4차 #5)** · 행위 · 학습자 ID · 목적 · 항목 | 앱 역할 `select, insert`만(수정 · 삭제 불가) | **2년**(산타 기본) |
| 운영 감사(로그인 · 설정 · 내보내기 등) | `audit_log` | 기관 · 일시 · 처리자 · 행위 · 상세(jsonb) | 해시 체인(SEC-0006, 개발자 2 병합 후) · 검증 `GET /api/audit/verify` | **2년** |
| 보안봇 · 긴급 차단 | `security.audit` | 처리자 · 종류 · 행위 · 대상 · IP 일부 가림 · `prev_hash` · `hash` | 해시 체인 적용 | 2년 |
| 권한 부여 · 변경 · 말소(`role.*` · `member.*` 등) | `audit_log` | 처리자 · 대상 운영자 · 변경 전후 역할 | `audit_log`와 같음 | **3년**(고시 제5조③) |
| 스튜디오 판단 기록(고영향 AI 등) | 기관 상태 + `audit_log` | 판단자 · 일시 · 사유 | `audit_log`와 같음 | 2년 |

- 보관 기간 2년은 정보주체 5만 명 이상 기관을 고려한 산타 기본값입니다. 계약서 · 기관 규정이 더 길면 그 기간을 따릅니다.
- 접속지 정보: 가디언 4차(2026-11-25)에서 `pii.access_log`에 `ip` 열을 추가했습니다(원값 · 접근 제한 저장). 로그 테이블은 기관 삭제 시 연쇄 삭제하지 않고, 보관 기간 만료 후 일 1회 파기 작업으로 지웁니다. 상위 기준은 [internal-plan.md](internal-plan.md) 8호입니다.

## 2. 점검 일정 · 역할
- **매월 첫 영업일**(주말 · 공휴일이면 다음 영업일) 점검, **5영업일 안** 완료.
- 점검자: 개인정보 보호책임자가 지정한 운영 담당 1명. 확인자: 개인정보 보호책임자(또는 대표님).
- 결과는 「월간 접속기록 점검 기록」(Google 시트, Santa Agent › 보안 폴더)에 남기고 3년 보관합니다. 기록에는 학번 · 학과 수준까지만 적고 이름 · 연락처는 적지 않습니다.

## 3. 점검 항목(매월)
| # | 항목 | 확인 방법 | 이상 기준 → 조치 |
|---|---|---|---|
| 1 | 해시 체인 무결성 | `GET /api/audit/verify`(정운영자) · 보안 화면의 `security.audit` 검증 | 끊김 1건이라도 → 즉시 사고 대응(README 5절 · 6절), 해당 구간 백업 대조 |
| 2 | 대량 개인정보 열람 · 다운로드 | 아래 쿼리 A | 한 처리자가 하루 학습자 1,000명 이상 열람 또는 내보내기 → 사유 확인서 받기 |
| 3 | 업무 시간 외 접근 | 쿼리 B(22시~06시, 주말) | 사유 없는 접근 → 처리자 확인, 반복 시 권한 축소 |
| 4 | 로그인 실패 · 잠금 | `audit_log` 로그인 실패 · 잠금 행 | 같은 계정 월 3회 이상 잠금 → 비밀번호 재설정 · MFA 확인 |
| 5 | 퇴사 · 권한 변경자 접근 | 운영자 목록과 처리자 대조 | 퇴사 후 접근 1건이라도 → 계정 즉시 정지 · 사고 판단 |
| 6 | 권한 변경 · MFA 해제 | `audit_log` 권한 · MFA 행 | 정운영자 승인 기록 없는 변경 → 원복 |
| 7 | 보관 기간 | 가장 오래된 행 일시 | 2년 미만인데 비어 있음 → 삭제 경위 조사 |
| 8 | 비밀값 스캔(12) | gitleaks · guard scan 결과 확인 | 탐지 1건이라도 → `secrets.md` 교체 절차 |

### 쿼리 예시(읽기 전용 계정으로 실행)
```sql
-- A. 처리자별 하루 열람 · 내보내기 학습자 수(지난달)
select tid, actor, date_trunc('day', at) as d, count(distinct learner_id) as n
from pii.access_log
where at >= date_trunc('month', now()) - interval '1 month' and at < date_trunc('month', now())
group by 1, 2, 3 having count(distinct learner_id) >= 1000 order by n desc;

-- B. 업무 시간 외 개인정보 접근(한국 시간)
select tid, actor, action, at at time zone 'Asia/Seoul' as kst
from pii.access_log
where at >= date_trunc('month', now()) - interval '1 month' and at < date_trunc('month', now())
  and (extract(hour from at at time zone 'Asia/Seoul') not between 6 and 21
       or extract(isodow from at at time zone 'Asia/Seoul') in (6, 7))
order by at;
```
쿼리 결과에는 학습자 ID(가명)만 나옵니다. 실명 확인이 필요하면 `pii` 역할의 열람 절차를 따르고, 그 열람도 `pii.access_log`에 남습니다.

## 4. 점검 기록 양식(시트 1행 = 1개월)

## 5. 남은 것(통합 채팅방 요청)
- `audit_log` · `pii.access_log`에 접속지(IP 일부 가림) 열 추가 — 고시의 「접속지 정보」 항목. DB 스키마 변경이라 Node · Java 함께(통합 채팅방).
- 월간 점검 쿼리를 보안 화면 「월간 점검」 버튼으로 묶기(가디언 Phase 1).
- 보관 기간이 지난 행의 자동 파기 작업(현재 수동).
