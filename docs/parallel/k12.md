# 학원(초중고) 운영 CRM

학원조아 CRM의 기능 요건을 참고해 디디쌤 기능으로 구현합니다. 화면 구성과 문구는 옮기지 않습니다.

## 1단계 범위
- 원생: 재원 상태, 학교 · 학년, 복수 보호자, 형제 자동 연결, 수강 이력, 전반 · 휴원 · 퇴원 일괄 처리, CSV 등록 · 내보내기
- 출석부: 날짜 이동, 등 · 하원, 사유, 진도, 과제, 메모, 보강, 휴강, 출석 통계, 시간표
- 성적: 시험 종류, 점수 입력, 미응시, 공동 석차, 누적 그래프, 성적 알림 기록, CSV
- 상담: 신규 문의, 원생 전환, 재원 상담, 분류, 상담자, 미상담자
- 수납: 월별 일괄 발생, 정기 납부일 자동 발생, 차량비, 할인, 분납, 수납 취소, 미납 알림 기록, 통계
- 운영 현황: 일일 요약, 월별 재원 · 신규 · 퇴원, 강사별 지표

## 자동 운영(v32.3)
운영자가 반복하는 일은 규칙으로 처리합니다. 설정은 홈 「자동 운영」과 각 화면의 「자동 운영 · 설정」 한 곳에서 켜고 끕니다(`crmCfg.auto`). 반 설정에서는 그 반만 끌 수 있습니다.

| 항목 | 기본 | 동작 |
|---|---|---|
| 수강료 자동 발생 | 켬(처음 켠 다음 달부터) | 정기 납부일, 없으면 매월 1일에 이번 달 수강료 생성 |
| 납부 마감 전 안내 | 켬 | 마감 3일 전 1회 |
| 미납 자동 독촉 | 켬 | 마감 3일 · 10일 경과 시 1회씩 |
| 출결 알림 | 켬 | 출결 입력 · 변경 시 |
| 미등원 알림 | 켬 | 시작 10분 후 출결 없음, 수업 중에만 |
| 수업 알림 | 끔 | 수업 당일 시작 전 |
| 데일리 리포트 | 켬 | 수업 종료 30분 뒤, 출결이 하나 이상 있을 때 1회 |
| 성적 알림 | 켬 | 재원생 점수(또는 미응시)가 모두 입력된 시험, 석차 제외 |
| 퇴원 정리 | 켬 | 퇴원 시 다음 달부터의 미납 청구 취소 |

- 실행 기록은 `crmRun`(날짜 · 항목 · 건수, 이름 없음)에 남기고 홈 · 학원 현황에 「오늘 n건 처리」로 보입니다.
- 홈 「오늘 할 일」은 학원 업무(출결 미입력, 결석 후 보강 미정, 마감 지난 미납, 처리 중인 신규 문의, 상담할 재원생)로 바꿉니다.
- 수납 설정 · 분류 설정은 「자동 운영 · 설정」 한 창으로 합쳤습니다.

## 2단계 보완(v32.2, 학원조아 대조)
- 반 설정: 과목, 수강 대상 학년, 정원(반 등록 · 전반 시 확인), 수강료 방식(월 고정 / 1회당). 1회당은 그달 수업 횟수(휴강 제외)로 청구합니다. 데이터는 `classes[].k12`.
- 보호자 자동 알림(반별): 출결 알림(기본 켬), 수업 알림, 미등원 알림(시작 10분 후 출결 없음), 데일리 리포트(출결 · 등하원 · 진도 · 과제, 개별 메모 제외). 발송 기록은 `classes[].crmDay[회차].auto` · `.daily`.
- 수납: 여러 달 선납(달마다 청구를 따로 만들고 바로 수납 가능), 영수증 출력, 교육비 납입 확인서(연도별), 원생별 현금영수증 정보(`members[].crm.cr` · `crn`, 영수증에는 번호를 가립니다).
- 상담: 「보호자 공유」를 고른 상담만 보호자 화면에 보입니다(`consults[].share`).
- 보호자 화면(`lscn-k12.js`): 자녀 관리에 학원 출결 · 진도 · 과제, 시험 성적(석차 제외), 예정 보강, 공유 상담을 붙입니다.
- AI SAM: 「오늘 데일리 리포트 보내줘」, 「○○ 3개월 선납 카드」.

## 화면 원칙(v31.9)
- 레일을 늘리지 않습니다. 원생 · 출석부 · 성적 · 상담은 `원생` 공간, 수납 · 학원 현황은 `운영` 공간 앞쪽에 둡니다.
- 표는 4~5열만 보여 주고, 나머지는 상세 창으로 옮깁니다. 원생 카드는 요약 먼저, 수정 · 이력은 눌렀을 때만 엽니다.
- 일괄 처리와 조건이 많은 일은 AI SAM에 맡깁니다. 예: 「이번 달 수강료 발생」 「미납 알림 등록」 「○○를 ○○반으로 전반」 「○○ 10만원 카드 수납」 「○○ 11월 20일 보강」 「○○반 내일 휴강」 「오늘 현황 요약」.
- 실행하는 명령은 계획 카드를 보여 주고 승인 뒤 처리합니다. 학원 명령은 브라우저에서 처리하고 원생 정보를 외부 AI로 보내지 않습니다.

## 데이터
| 위치 | 내용 | 서버 암호화 |
|---|---|---|
| `members[].crm` | 원생 부가 정보 | JSON 전체 |
| `crmLeads` | 신규 문의 | 이름, 학교, 보호자, 연락처, 메모 |
| `crmHist` | 수강 이력 | 메모 |
| `classes[].crmDay` · `k12Exams` · `makeups` | 출결 부가 기록, 성적, 보강 | JSON 전체 |
| `consults`, `parents`, `msgs` | 기존 구조 사용 | 기존 대상 |
| `inbox`, `chat` | 알림함, AI SAM 대화 | 알림함 전체, 대화 글 · 제목 · 카드 |

주소, 직장, 집전화, 사진은 받지 않습니다. 강사에게는 담당 수업과 원생의 재원 상태만 전달합니다.

## 연동 전 한계
- 알림은 메시지 기록으로 남습니다. 문자 · 알림톡 · 보호자 앱 전달은 업체 연동 후 시작합니다.
- 강사 화면의 알림 기록은 서버에 저장되지 않으므로 성적 알림 버튼을 숨겼습니다.
- 정기 납부일 자동 발생은 운영자가 수납 화면을 열 때 실행합니다. 서버 예약 작업이 아닙니다.
- 일일 요약은 입력된 기록을 규칙으로 정리합니다. 외부 AI로 원생 정보를 보내지 않습니다.
- 분납 중인 청구는 보호자 온라인 결제 대상에서 빠지며, 현장에서 수납합니다.
- 자동 운영은 운영자(정운영자 · 부운영자)가 스튜디오를 열어 둔 동안 1분마다 확인해 처리합니다. 서버 예약 작업이 아니므로, 아무도 열지 않은 날은 다음에 열 때 처리합니다(미등원 · 수업 알림은 그 시간이 지나면 보내지 않습니다).
- 보호자 화면의 학원 기록은 가족 연결(데모 · 로컬 데이터룸)에서 보입니다. 실서버 보호자 계정 연결은 코어에 아직 없습니다.
- 현금영수증 · 카드 전표는 국세청 · 결제 업체 연동 후 발급합니다. 지금 영수증은 학원 발행 영수증입니다.

## 2단계 후보
교재 재고 · 묶음과 교재비 청구, 월별 상담 현황, 직원별 메뉴 권한, 원생 목록 출결 필터, 성적 파일 첨부, 문자 예약 발송, 다중 사업자, 인사서류, 키오스크 결제.
