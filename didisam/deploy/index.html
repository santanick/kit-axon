네 가지 방식으로 설치합니다.

디디쌤 스튜디오는 고객 기관마다 데이터룸을 따로 둡니다. 데이터 · 파일 · 암호화 키 · AI 사용량 · 감사 로그 · 백업이 기관 단위로 분리되고, 기관의 보안 요건에 맞춰 공유 SaaS부터 기관 서버 설치형까지 같은 프로그램으로 배포합니다.

1. 배포 모델 4종

A공유 SaaS대상 학원 · 평생교육원 · 소규모 기관데이터 디디쌤 클라우드(서울 리전)격리 기관별 DB 스키마 + 행 수준 보안 + 기관별 암호화 키 + 파일 경로 분리설치 관리 콘솔에서 테넌트 생성(즉시)

2. 한 코드, 네 가지 설치 — 이식형 스택

Firebase처럼 특정 클라우드에만 있는 서비스는 고객 클라우드 · 설치형에 옮길 수 없습니다. 그래서 운영 서버는 어디서나 돌아가는 표준 구성으로 만들고, 클라우드마다 관리형 서비스로 바꿔 끼웁니다. 화면 코드는 바뀌지 않고 데이터 포트(브라우저 저장소 ↔ API)만 바뀝니다.

4. 설치 절차

공통 — 테넌트 구성 파일

  1. 스튜디오 설정 › 계정 · 데이터 › 데이터룸 · 배포에서 배포 모델과 세부 구성(클라우드 · 리전 · AI 경로 · 로그인 · 키 · 외부 연결)을 고릅니다.
  2. 「설치 구성 파일(YAML) 내려받기」로 didisam-tenant-<테넌트 ID>.yaml을 받습니다(예시).
  3. <...> 값(도메인 · SSO · KMS 키)을 기관과 함께 채웁니다. 비밀값은 파일에 쓰지 않고 비밀값 저장소에 둡니다.

A 공유 SaaS

  1. 디디쌤 관리 콘솔에서 구성 파일로 테넌트를 만듭니다(스키마 · 데이터 키 · 저장 경로 · 하위 도메인 자동 생성).
  2. 운영자 계정을 초대하고 개인정보 처리 위탁 계약을 맺습니다.

B 전용 클라우드 · C 고객 클라우드

  1. Terraform으로 KMS 키 · DB · 버킷 · 서비스 계정을 만듭니다(C는 기관 계정에서, 디디쌤에는 배포 · 모니터링 권한만 위임).
  2. Kubernetes(GKE · EKS · AKS · NKS)에 Helm 값으로 배포합니다. 기관 하나 = 네임스페이스 하나.
  3. SSO 메타데이터 연결 → AI 경로 확인(Vertex AI · Bedrock은 기관 계정에서 Claude 모델 사용 승인과 리전 가용성 확인) → 교차 접근 · 복구 점검 후 개통.

D 설치형

  1. 오프라인 번들(컨테이너 이미지 tar + 서명 + 체크섬)을 기관 반입 절차로 들여와 docker load로 올립니다.
  2. docker-compose.yml · env.example(.env로 복사) · 구성 파일을 두고 docker compose up -d(대규모는 Helm). 내부 네트워크는 외부 인터넷이 차단된 상태로 시작합니다.
  3. LDAP/AD 또는 SAML 연결, 내부 LLM 주소(없으면 AI 끔) 입력, 기관 SIEM으로 감사 로그 전송.
  4. 업데이트는 분기별 오프라인 번들로 반입 · 적용합니다(원격 접속 없는 운영 가능).

서버 사양(초기 추정): 설치형 소규모(동시 접속 300명) — 8 vCPU · 32GB · SSD 500GB 1대 / 중규모(동시 2,000명) — 앱 2대(8 vCPU · 16GB) + DB 1대(8 vCPU · 32GB) + 저장소. 내부 LLM은 GPU 서버가 별도로 필요합니다. 영상 용량에 따라 저장소를 늘립니다.

5. 공공기관 · 기업 확인 사항

  • 공공기관 클라우드: 클라우드 보안인증(CSAP)을 받은 클라우드 · 서비스인지 기관 요건을 먼저 확인합니다(고객 클라우드 모델로 기관이 지정한 공공 클라우드에 설치).
  • 망분리 · 폐쇄망: 설치형으로 설치하고 외부 연결은 모두 끈 상태에서 시작합니다. 외부 AI를 쓸 수 없으면 내부 LLM 또는 AI 끔(규칙 엔진)으로 운영합니다.
  • 보안성 검토 · 개인정보 영향평가: 기관 절차에 맞춰 구성도 · 데이터 흐름도 · 수집 항목표를 제출합니다. 대학은 학번 · 학과만 저장합니다.
  • 데이터 국외 이전: 모든 모델의 기본 리전은 국내입니다. AI 경로가 국외 리전을 쓰는 경우 기관 동의와 고지가 필요합니다(Vertex AI · Bedrock의 국내 리전 가용성 확인).
  • 계약 종료: 데이터룸 전체 내보내기(JSON · 파일) → 기관 확인 → 키 폐기로 파기 → 파기 확인서.
